# Orb 开发版 · Mio

此目录是 DSH desktop profile 已配置加载的开发包，不是原版备份。

**`.31`：修陪伴请求被拒。** `companion-stream.js` 的 `maxTokens` 下限原本硬编码 256，而 `.24` 把陪伴输出压到 192（30 字回复只需约 70 token），于是每次陪伴请求都抛 `Invalid companion output limit`、界面显示"陪伴请求失败，已放慢重试"。现在下限改为 64，上限 4096 不变。

**`.30`：修 list_controls 与名字匹配。** `list_controls` 原先把 `render` 返回成字符串，DSH 会做 `content.some` 直接报 `content.some is not a function` —— 改成返回 blocks 数组；名字匹配改为三级（精确 → 去掉尾部 ` (Alt+F)` 之类的后缀 → 子串包含），`设置及其他` 现在能点到 `设置及其他 (Alt+F)`；`click(name)` 失败不再现场遍历（遍历会关掉刚打开的菜单/弹层），只查缓存并报能力等级；`list_controls` 每条附 `center=x,y`，可以探一次后直接按坐标点；helper 改成**纯 ASCII**（Windows PowerShell 5.1 读无 BOM 的 UTF-8 脚本会乱码导致解析失败），并过滤掉最小化窗口的天文负坐标。

**`.29`：UIA 发现层。** 新增 `list_controls` 工具（列当前窗口有名字的可点元素，支持 filter/limit）；名字表按「应用 + 窗口句柄」缓存 10 分钟（缓存的是名字，坐标每次重查）；应用能力表持久化到 `~/.dsh/storages/uia-capabilities.json`（tier A/B/C，跨会话）；`click(name)` 找不到时不再只抛错，而是回传"这个软件到底支不支持名字点击 + 可用名字"。实测：DSH 窗口 270 个有名元素（首次 1.5s，缓存后 0ms）、explorer 0 个（判 C 档）；helper 修了虚拟化元素 ±∞ 矩形导致的崩溃。

**`.28`：修 `.27` 的 schema 事故。** `.27` 把 `click` 的 `position` 写成 `required: false`，而 DSH 的工具 schema 校验**只认 `required: true`**，出现 `false` 会让整个 computer-use 插件报 `unsupported JSON schema: parameters.position.required must be true when present`，连带 `computer-use` 预设的会话全部变成"会话不可用 / 标题显示 session id"、侧边栏工作区列表也空掉。修法：可选参数的写法是**整条 `required` 不写**（和 `button`/`count`/`modifiers` 一致），不是写 `false`。

**`.27`：UI Automation 命中 + 按名字点击。** 新增常驻 UIA 小工（`uia-helper.ps1` + `uia-bridge.js`，PowerShell 常驻、JSON 行协议、进程退出自动清理）：`click` 的命中信息升级到**控件级**（`Button · 增大字体 (in 文档1 - Word)`），并新增 `name` 参数——`click(name:"增大字体")` 直接让 UIA 找到元素矩形、点它的中心，不再靠模型估坐标；找不到时**拒点**并回传附近可点的名字。`position` 因此变成可选（二选一）。实测 Word：`ElementFromPoint` 1ms、`FindFirst(name)` 35–79ms、首次启动约 700ms；UIA 矩形与截图/点击是**同一物理像素空间**（root 2582×1462 == 截图 bounds），不需要 DPI 换算。

**`.26`：点后变化判定。** `click` 现在会抓点击点周围 220×160 的原始像素（BGRA，不含光标），点前、点后各一次做差分，返回 `changed`（变化像素占比 > 0.3% 才算）与 `changedRatio`；文案里直接说"这里变了/没变"，没变时提示"可能点在空白处，先重新观察再点"。数据来自原生层新加的 `captureRoiRaw`（BitBlt + GetDIBits，不解码 PNG），不会拉长点击链路。局限：只看点击点周围这一块，弹窗开在别处时可能判成"没变"。

**`.25`：点击命中反馈。** computer-use 的 `click` 现在返回 `Hit: 进程 · 窗口类名 · 标题`（点前/点后各一次）、`activated`（前台有没有被这次点击改变）、`dpi`；新增可选参数 `expect`，命中不符就**拒点**并报出实际窗口。用于解决"点空了还是点中了看不出来"——36 条实测日志里有 15 次是"没反馈就反复点同一坐标"。局限：命中信息只到**窗口级**（类名/标题/exe），不到 UIA 控件级。

**`.17`：屏幕陪伴改两行浮条。** 屏幕陪看不再自动弹对话面板（会挡画面，每 2 秒截图还会闪），改成悬浮球旁边一条 286×58 的两行磨砂浮条：第一行状态（`看屏中 · 采样 N · 发言 M`，暂停时点变黄），第二行是最近一句（新句从下往上替换，不跑马灯）。窗口 click-through、不抢焦点、不抢任务栏，win32 上常驻屏蔽采集。数据走 `~/.dsh/dsh-orb/companion-ticker.json`，helper 每 700ms 轮询；停止陪伴后淡出、3 秒隐藏。点球仍然会弹出面板（只是不再自动弹）。

**`.16`：屏幕陪伴不再闪。** 屏幕陪伴每 2 秒截一次图，截之前要把自己的悬浮球/面板"挡出画面"——`setContentProtection(true)`，截完再关掉。Windows 上这个调用**每调一次都要重绘一帧**，于是球和面板跟着闪。现在球与工具条和观察框一样**常驻**保护（`resting`），并给 `cloak.sync` 加了"值没变就不再调用"。副作用：悬浮球不再出现在截图和录屏里（和观察框一致）。

**`.15`：人设统一到全局。** 装了 `dsh-persona-dafeiyu`（设置在「大肥鱼」页签）之后，主会话（含悬浮球面板里的会话）走它；Orb 的**陪伴/指导**是直传 system、绕开系统提示词注册表，所以从现在起会自动从它的 HTTP 桥抄当前人设：`character-card.js` 每 60 秒拉一次 `/api/dsh-persona-dafeiyu/{status,persona}`，人设文本当基准，只保留自己的边界句与 60 字上限。角色卡里的人设**留空 = 跟随全局**（这时不会再加「你的名字是…」，避免两个名字打架）；填了就优先用你自己写的。人设被关掉或插件不在了会立即退回空文本，不偷偷沿用旧内容。

**`.14`：角色卡。** 设置 → 角色：名字、全局人设、指导单独人设（留空继承全局）、陪伴每句上限（默认 60 字，20–120）。只作用于 Orb 自己发起的调用（面板聊天、屏幕陪伴、指导），**不动 DSH 主会话的预设**。注入顺序是"角色卡 → 一句边界 → 模块原有硬约束"，所以 JSON 格式、无工具、不能编造这些边界不会被角色卡改写；一个字都不填时提示词与之前逐字节一致。陪伴的回复超长会按最后一个完整句截断（60 字上下正好是一整行弹幕的宽度），同时把输出预算从 512 token 降到 256 以免撞上限后被整条丢弃。存在 `runtime/character/character.json`，保存即生效。

**`.13`：陪看期间不画「观察框」。** 那条青紫渐变的边框属于 `computer_use`：列完屏幕后画一圈，**只在下一次列屏幕或回合结束时清除**。视频陪看是一轮阻塞的回合，从头到尾等不到 `turn/end`，边框就钉在开始时那个窗口的位置，切到浏览器也不动。现在陪看会期内把它压成 null（开始时先清一次，结束时恢复），指导与桌面任务那些场景不受影响。

**`.12`：陪伴控制与状态面板。** 设置里的那张卡改成与页面其余卡片同一套样式，并把三件事分开显示：**已保存的模块 / 未保存的修改 / 实际在运行的模块**——只改下拉框不保存时会出现“未保存：改为…”，已保存的标记不动。开始/暂停/继续/停止四个按钮只作用于已保存的模块；启动先显示“启动中”，等原模块真实报出运行状态才显示运行中。视频模式分三行报告播放链路（本机服务是否可达 / 扩展是否在报 / 当前位置是否新鲜），位置过期显示“等待播放信息”而不继续显示旧秒数；对白来源逐词翻译（站点字幕 / 语音识别 / 语音识别未配置 / 没有音轨…）。面板每 2.5 秒读一次纯读状态接口，页面隐藏即停，不产生模型或 ASR 请求。暂停视频仍用原插件停表，继续时重新跟随播放位置。

**`.11`：手动选择陪伴模块。** 设置 → Orb 开发版 · Mio → Watch 陪伴设置 → 陪伴模块，可选“屏幕陪伴（Watch）”或“视频陪看（watch_together）”。保存后发送“开始陪伴”，使用所选模块；不自动识别或切换。视频陪看的启动、停止、状态请求交给原生 DSH 工具流程，普通消息不被屏幕 Watch 拦截。视频设置仍由原插件管理。切换前先停止当前陪伴；旧配置默认保持屏幕陪伴。

**`.10`：Watch 设置与回复兼容修复。** DSH 设置 → Orb 开发版 · Mio → Watch 陪伴设置，可保存本地采样间隔（1–10 秒）、自动看图间隔（10–180 秒）、主动发言间隔（0–300 秒）、主动陪伴和静默降频开关。保存暂停当前陪伴，发送“继续陪伴”应用；配置保存在项目 `runtime/companion/settings.json`。完整普通文本回复现在也能正常显示，损坏 JSON 跳过并计入状态，不再按网络错误停止陪伴。视频输入只含画面，没有声音。
