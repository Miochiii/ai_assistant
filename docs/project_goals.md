# 项目目标与路线约束

状态：最高层项目约束。若与更早的局部计划冲突，以本文为准；具体接口和安全规则仍以对应协议文档为准。

输入面扩展的约束设计见 [统一键盘、文本、滚动与拖拽协议评审](../log/2026-10-31-unified-input-protocol-and-failure-review.md)。它当前是设计决策，不是已实现能力；E0 基础、键盘/文本/滚动/拖拽均仍待实现和验收。

## 目标

做**通用桌面软件助手**：把模型已有的操作知识，转化为在用户当前桌面上实际完成任务的能力。

核心闭环：

**理解目标 → 观察当前界面 → 规划下一步 → 定位目标 → 受控执行 → 验证结果 → 继续、重新规划或停止。**

## 分工

1. **模型负责规划。** 模型通常已经知道软件的操作步骤，不必为每个软件重新编写流程。但操作顺序只是计划，必须根据当前界面、弹窗、焦点和执行结果调整，不能盲目连续点击。
2. **通用底座负责定位与执行。** 窗口身份、客户区、DPI、坐标映射、截图、键鼠输入、授权、取消和结果验证统一实现，避免为每个软件建立独立操作链路。视觉优先，标准窗口 API、可选 UIA/OCR 可以辅助。
3. **权限由宿主管理。** 模型提出操作，固定执行器检查并执行。知道操作方法不等于获得操作授权；输入送达不等于任务成功。
4. **PreAct 负责复用已验证流程。** 首次任务由模型探索并验证，重复任务通过当前状态检查、重新定位和本地重放减少模型调用。超出适用条件时停止并交回规划层，不用旧坐标硬点，不在重放内部悄悄调用模型续跑。
5. **记忆是辅助能力。** 保存用户偏好、任务状态与可复用经验，不能替代当前界面证据，也不能因记忆里记录过成功就跳过验证。

## 两条线路

### 第一条线：当前主线

完善现有视觉规划、通用窗口定位、受控执行和结果验证，逐项扩展输入能力；验证同一套底座能在不同软件中完成任务，并正确处理异常。

### 第二条线：暂缓实验

借鉴 VLX-Seek／SoM 的“候选区域生成 → 编号 → 模型选择 → 宿主映射原图位置”。当前只预留接口，默认关闭；第一条线成熟后再做独立只读对照实验，通过后接入同一执行底座。具体接口见 [grounding 第二线接口计划](../log/2026-10-30-grounding-second-track-interface-plan.md)。

## 判断是否偏离

新工作是否增强跨软件复用的闭环能力，或提高已验证流程的可靠性与效率。软件相关操作知识和用户特化流程可以存在，但不应因此不断新增应用专用底层代码。

近期验收重点是：**同一套底座跨软件完成任务，结果可验证，失败可解释，异常时能停止或恢复。**

不把演示成功、离线测试通过或模型给出正确步骤，当成完整实机能力已经实现。
