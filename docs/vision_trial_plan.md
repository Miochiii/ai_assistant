# B01 只读视觉小试准备

更新：2026-10-24。首轮已使用 Harness 原生 SDK 的隔离入口完成 1 次官方 Flash 识别，使用用户批准的最多 3 次、¥0.50 预算。状态识别及目标中心通过，预测框边缘存在误差；结果见 `../results/b01/flash-readonly-20261023/evaluation.json`。试验已关闭，不继续消费余量。运行中会话工具调用尚未验证。

## 最新路线：直接使用 Flash

审阅 Orb 后，首选 `desktop_observe` → Harness 图片附件 → 当前 Flash 识别并输出位置，无需先安装 Vision Toolkit 或申请另一套 API。0.2.0 已实现可选图片内容块并通过离线检查，用户已报告重启；当前 `configs/desktop-observe.json` 的图片开关仍为 false。隔离小试通过不等于完整会话的工具调度和预算控制通过。实现说明见 `../plugins/dsh-desktop-observe/README.md`，设计来源见 `orb_visual_reuse.md`。

首轮计划改为对一张当前截图直接询问应用/模式/显示值，并给出等于按钮的位置；记录附件实际尺寸、截图边界、原图哈希和模型回答。使用一套明确的像素坐标约定并独立看图核对，不提供期望答案或固定按钮坐标。真实轮次可能包含多次 Harness 模型请求，需确认总调用限制和费用后再执行。

以下 Vision Toolkit 方案保留为备选，不再作为下一步默认安装计划，其两次视觉请求限额不自动适用于原生 Flash 链路。

## 接入方式

DeepSeek/Harness 调度 `desktop_monitors` → `desktop_observe`，产生当前可见画面的 PNG 及坐标元数据。视觉工具读取 PNG，返回画面描述或目标框，再由 Harness 解释结果。本阶段没有输入工具。

本地下载的 Vision Toolkit 0.1.47 提供两种相关接口（核对 `src/tools.ts`、`src/config.ts`，不代表云服务已核验）：

- `vision_glance({images:[path],query})`：回答图片问题，输出文字。用于确认计算器模式、显示值及遮挡。
- `vision_ground({image:path,target,preview:true})`：定位单个具名目标，输出像素框及标注图。用于定位「等于按钮」，只展示，不点击。

`vision_ground` 的坐标基于实际分析图像；插件可能压缩或缩放输入。必须使用返回的图像尺寸和原截图 `capture_bounds` 映射屏幕位置，不能将目标框直接当成全桌面坐标。目标缺失、多义、越界或图像来源不匹配时，记为无法确定。

## 首轮样本与检查

1. 用户保持计算器可见，拍一张新截图。仅准备计算器所在的可见区域作为外发图像，现场决定区域，不复用旧坐标；保存原图哈希。
2. 一次 `vision_glance`：询问应用、模式、当前值、是否有遮挡。不告知预期为 0，不要求模型猜测。
3. 一次 `vision_ground`：定位等于按钮，保留返回原文、分析图像尺寸和标注图。模型目标框必须落在可见按钮内；由人看图独立核对。
4. 保存 run/session、模型 ID、供应商、图像哈希、请求数、token/费用（供应商未提供则记未知）、延迟和核对结果。截图成功、框格式有效与语义识别正确分别记录。

首轮只验证上述开发样本。后续需移动或改变窗口大小、切换记事本等再采新图，才能检查泛化，不以单图正确宣称通用可靠。

## 调用前仍需落实

- 明确视觉服务和模型，查官方当前图像能力、价格及数据发送目的地；不沿用下载文档中「免费」的承诺。
- 检查真实请求的输出 token 上限、重试和调用数限制。拟定首轮最多 2 次视觉请求、并发 1、自动重试 0；这些目前只是试验要求，尚未在 Vision Toolkit 中配置或验证为硬限制。
- Harness/DeepSeek 的规划调用可能另计费用，需要与视觉请求一起计入预算，不能把「2 次视觉请求」说成总共 2 次 API。
- Vision Toolkit 默认开启图像输入变体和自动路由切换。最初只做显式工具调用，安装前审查并关闭自动切换，避免普通贴图意外触发视觉服务。
- 先核验依赖和隔离方式，再安装视觉插件；不借用或改变 RAG 环境，不安装 CUDA。预算明确并获得用户批准后才运行远程诊断或识别。

本文件不包含 API 密钥。上述 Vision Toolkit 备选没有安装或执行；它不继承本次已关闭的 Flash 试验额度。
