## 3. 借鉴范围：选择区域，不绑定特定模型

VLX-Seek 的启发是：模型选择已有区域引用，程序查表获得目标位置，降低自由生成坐标带来的错误。但候选区域漏掉目标时，选择器无法凭空恢复目标；这不是自动获得正确坐标的保证。

第二条线首个实验可以沿用已有 DeepSeek 视觉能力，向截图添加候选编号，让模型返回编号。它接近 Set-of-Mark 视觉标注，不等价于 VLX-Seek 训练过的区域编码与特殊 token 能力。不要把 `<objN>` 原样放进提示词，就宣称已复现 VLX-Seek。

当前不依赖 VLX-Seek 权重、CUDA、Intel 核显/NPU适配或新 API。模型可用性和硬件限制不能成为第一条线的依赖。

候选来源今后可包括通用 UI 检测、OCR 与控件区域结合、标准 UIA 元数据，以及有明确适用范围的局部视觉匹配。OCR 字框不等于按钮可点击区，UIA 边界不等于当前无遮挡。候选来源都只提供证据，不授予执行资格。

## 4. 逻辑接口：公共输入输出，内部策略可替换

以下名称和字段为建议契约，不代表工具已注册或配置已存在。可以采用项目现有命名，不要求一一新增类、文件或 Harness 工具。

```text
GroundingRequest
      │
      ├─ existing_direct：现有模型坐标结果的宿主适配
      ├─ existing_patch：现有局部匹配结果的宿主适配
      └─ candidate_selection：第二条线，暂不启用
              propose_candidates → make_analysis_view → select_candidate
              → validate_selection → resolve_original_point
      │
GroundingResult（定位建议，不是执行权限）
      │
宿主校验 → 现有 ActionClient / Node 动作入口
      │
固定执行器复核 → 实际输入回执 → 独立结果验证
```

第一条线不需要为包装结果额外调用一次模型。既有模型调用结果可由宿主适配成统一结果；第二条线选择器才在未来实验中使用单独的模型适配。

### 4.1 GroundingRequest：由宿主构造

| 字段 | 最小语义 |
| --- | --- |
| `schema_version`、`request_id` | 协议版本和本次请求标识 |
| `task_id`、`session_id`、`request_generation` | 任务/会话和取消、重规划的代次；运行期产生，不采信模型填写 |
| `observation_ref` | 原始观察 ID、图片 SHA-256、原图尺寸、宿主可解析的清单引用 |
| `window_context_ref` | 对应的 context ID、窗口绑定和 geometry revision 引用；身份细节复用现有契约 |
| `target_spec` | 目标语义、上下文锚点、预期控件类型与操作意图；可有历史参考，但不能以旧坐标为当前答案 |
| `region_constraint` | 当前已允许读取的观察内范围，不允许定位器自行扩展到其他窗口 |
| `policy` | `read_only / action_candidate`、允许的方法、候选数量/输出长度上限、截止时间、远程图片策略与调用次数上限 |

定位器只获得完成定位所需的图片/数据和受限模型客户端，不获得输入执行器、授权管理器或任意 shell。方法名称必须映射到宿主登记的实现，不能让模型输入 import 路径、可执行命令或远程服务地址。

取消信号、时钟和模型调用客户端建议通过运行期依赖传入；不要把进程对象塞进可持久化 JSON。新增字段的必填规则按版本定义；旧观察缺失必要绑定时返回不支持，不能以空串、零或当前窗口信息补造旧证据。

### 4.2 GroundingResult：只表示定位结论

```text
schema_version, request_id, task_id, session_id, request_generation
observation_id, image_sha256, context_id, geometry_revision
method, method_version
status: found | not_found | ambiguous | unknown | unsupported | cancelled
target: null 或 {coordinate_space: original_image_px, point: [x, y], bbox?}
candidate_ref: null 或 {candidate_set_id, candidate_id}
reason_codes, evidence_refs
metrics: proposal_ms, render_ms, model_ms, resolution_ms, total_ms,
         model_calls, input_tokens?, output_tokens?, retries
```

- 上述绑定由宿主附加并校验，不由模型自述作为证据。非 `found` 时 `target=null`。
- `found` 表示有目标定位建议，不表示已授权、已点击或任务成功。`read_only` 结果禁止进入执行入口。
- `unknown` 表示模型超时、响应损坏或证据不足；`not_found` 仅表示当前允许观察范围中未定位到，不断言整个应用不存在该目标。
- 没有 token 用量数据时记 `null`，不能记成 0。相似度和模型自报置信度只能解释结果，不能充当授权或通用通过阈值。
- `point` 使用原始观察中的有限整数像素坐标；矩形统一为 `{left, top, width, height}`，右/下边界排除。非法、越界或不一致的结果拒绝，不夹到边界上。

现在可先约定此返回形状。将现有 PreAct 的点/None 回调升级为完整结果对象时，通过兼容适配层保留旧调用行为，避免大范围修改重放状态机。

## 5. 第二条线专用契约：候选表与选择回答分开

### 5.1 CandidateSet：宿主持有，绑定一张原图

```text
candidate_set_id, schema_version, content_sha256
request_id, request_generation, observation_id, image_sha256
context_id, geometry_revision, original_image_size
generator_id, generator_version
coverage: complete_for_declared_region | partial | unknown
truncated: boolean
candidates[]:
  candidate_id
  bbox_original_px
  source, source_evidence_ref
  label_hint?, role_hint?
  enabled_state: enabled | disabled | unknown
  visibility_state: visible | blocked | unknown
  click_point_original_px?   # 仅在有可解释依据时给出
  click_point_evidence_ref?
```

`coverage` 描述生成流程是否覆盖了声明范围，不代表候选召回率100%。模型仍可能误选，检测器仍可能漏检。

编号只在当前候选集合内有意义。重新截图、裁剪、筛选、排序、合并或重新编号，都产生新集合 ID 和内容摘要。去重先于编号；重叠框不能不加判断全部合并，按钮与所属面板可能是不同对象。

缓存键至少包含原图哈希、观察 ID、窗口几何版本、生成器版本和生成配置摘要；同样像素的旧截图不继承本次执行资格。缓存只优化计算，不跳过观察新鲜度和一次性消费检查。

### 5.2 AnalysisView：分析图不能替换动作原图

保存 `analysis_view_id`、对应候选集合及摘要、原图引用、分析图哈希/尺寸、裁剪缩放变换；模型附件若被宿主重新缩放，记录实际交付尺寸及其关联。缩放后编号不可辨认时停止，不让模型猜。

首轮只做同尺寸编号叠加，不同时引入新裁剪/坐标变换。编号位置避免遮挡关键标签，保留未标注原图作为对照。后续裁剪或缩放必须用显式变换，不能复用仅处理整图等比关系的函数去猜裁剪偏移。

原始 `screen.png`、`source.rgb`、清单和哈希保持原义。标注图为派生分析材料，不能覆盖原文件，不能伪造 `resized=false` 或 click-binding。执行请求永远引用当前合法的原始观察。

### 5.3 SelectionReply：模型选择 ID，不修改候选表

模型最小回答可为：

```json
{"status":"selected","candidate_id":"c017"}
```

或 `{"status":"not_found"}`、`{"status":"ambiguous"}`。这是结构示例，不是已注册工具请求。关联的集合 ID、请求代次和图片映射由宿主维护；模型回传这些字段时也必须与宿主上下文严格一致。

模型不得返回任意屏幕坐标来替代无效编号，不得修改窗口、grant、框范围或执行类型。一个目标返回多个 ID、不存在的 ID、缺字段或不合法值，都拒绝；不能选列表第一项凑合继续。

### 5.4 从已选区域解析到点

宿主按顺序确认：请求未取消/超时且代次仍有效 → 原始观察与候选集合绑定一致 → 编号属于本集合 → 候选区域位于允许范围 → 目标交互状态有充分证据 → 解析当前原图内的交互点。

不能统一采用框中心：文字、面板、空心控件、复合按钮、遮挡区域可能使中心不可点击。第一轮只读实验可把中心作为待评估的候选策略；后续执行接入必须说明交互点的依据，无依据返回 `unknown`。检测器或 UIA 自述“可见/启用”也不免除执行器当前检查。

定位结束后窗口移动、布局改变、出现遮挡或用户抢占时，交给现有检查拒绝；需要新的观察和定位，不平移旧编号坐标强行继续。候选表哈希只用于内容一致性，不是对恶意本地同用户代码的安全签名。

## 6. 第一条线保持的执行与 PreAct 边界

1. 规划与重放共用固定执行器。第二条线永远不能直接发鼠标键盘事件、激活窗口或隐式创建授权。
2. PreAct 的已知任务继续走现有局部匹配。匹配失败仍 `replan_required`；未来由外层规划器决定是否启用第二条线，不在一次重放里暗中联网重新规划。
3. 没有合法 action-ready 观察的历史截图，只能用于离线定位评测；不能补造当前清单后点击。
4. 新定位策略不自动晋升程序、更新参考模板或写入长期记忆。实验选择正确不等于任务结果通过，更不等于程序验证成功。
5. 如果将来程序选择的定位算法、配置或适用范围变化，需要按现行版本/proof规则重新验证相关程序，不能把旧 proof 自动赋给新语义。当前预留接口不要求批量改写旧程序。
6. 超时/取消后的迟到结果不得执行、写 checkpoint 为成功或污染新的任务。若取消发生在动作发出后，沿用现有 `unknown_after_input` 等语义，不把定位器无副作用误写成整个任务没有输入。

## 7. 配置与最小落地清单

建议区分“实现可被注册”和“策略允许实际调用”。第二条线默认关闭、显式选择，不能因为模块安装了就自动加入运行链。不要现在创建虚假的可用检测器或对外暴露尚未实现的工具。

DeepSeek 当前只需在相关修改时保证：

- 定位输入保留目标语义、原始观察引用和窗口上下文，避免函数只剩裸 `x/y`。
- 保留已有 `locator` 注入；通过薄适配把已有结果转成可解释结果，默认方法与行为不变。
- 通用规划定位与 PreAct 局部匹配分开配置，不能共用一个开关导致重放开始调用云端模型。
- 动作入口仅接受宿主验证后的原图位置与现有观察契约，不接受模型构造的候选注册表或任意路径。
- 新逻辑支持 deadline/cancel，并能保存方法、版本和失败原因；跨语言字段保持一致，不做一套 Python 规则、一套 JS 规则。

若实际修改了边界代码，至少验证：默认流程结果不变；未启用第二条线时零额外模型调用；非 found 不执行；旧观察/错集合/迟到结果被拒绝。可以使用 fake provider/固定夹具，不需要此时开展真实第二条线实验。本文不要求仅为写文档而运行实机测试。

## 8. 第一条线何时算成熟、第二条线何时启动

“成熟”指拟覆盖的任务范围具备可重复验收，不要求先完成所有应用、所有输入类型。至少满足：

- 在计算器、记事本等不同界面上，现有观察—定位—执行—验证流程能重复完成既定任务，成功有独立证据。
- 对声明支持的移动/尺寸/DPI场景有验证；不支持的情况明确拒绝，不凭缩放比继续点击。
- 授权、前台/遮挡、取消/超时、用户抢占、旧观察重用等边界有可解释结果；没有未解决的误点或失败后继续输入问题。
- PreAct 对已验证任务能本地重放，失败退出；不会靠反复重试掩盖失败。
- 已记录第一条线的成功率、失败分类、模型调用/用量和完整链路延迟，作为对照基线。

上述状态由验收记录支持，不能根据本日志自动宣告达标。达到后在阶段交接时报告，再安排第二条线；当前没有启动实验的任务，不因新增日志触发后台调用。沿用用户届时有效的 API 与图片使用授权，不重复索要已覆盖的许可，也不扩展发送范围或供应商。

## 9. 后续实验顺序与接入门槛

### 阶段 A：验证编号选择机制，只读

使用允许用于该实验的静态截图，建立目标真实可点击区域/允许点及缺失、歧义标签；同一图比较原图坐标输出与编号选择。候选可先人工标注，但候选制作不能专门给正确答案突出标记，编号顺序应做扰动检查。

这一步测的是候选存在时的选择收益，不是自动候选生成能力。两组保持相同目标、模型版本和输出限制；分别运行在干净的短上下文中，避免 A 的结果泄露给 B。标注图和原图一起发送时，要计入两张图的实际开销。

### 阶段 B：加入真实自动候选生成，只读

冻结生成方法和参数，再在独立截图上测试。人工候选结果与自动候选结果分开统计，不能用人工补框后的成绩冒充端到端准确率。当前阶段不以应用名称写专用定位分支。

覆盖窗口移动/缩放、不同 DPI、布局重排、同名或重复图标、小按钮、禁用目标、弹窗/遮挡、目标缺失。对于检测不到的目标，返回 unknown/not_found并计入失败，不通过排除样本美化结果。

### 指标与门槛

| 指标 | 统计口径 |
| --- | --- |
| 候选覆盖率 | 目标存在时，是否产生包含有效交互区域的可用候选 |
| 条件选择正确率 | 候选已经包含目标时，模型能否选对；与覆盖率分开 |
| 端到端定位命中率 | 全部目标存在样本中，最终点是否落在标注的允许区域；拒绝也占分母 |
| 缺失/歧义/禁用误选率 | 不该确定选择时是否仍输出可执行目标；不能只统计正样本 |
| 完整耗时 | 候选生成、绘图、模型、解析及失败重试，报告中位数与 P95 |
| 云端消耗 | 记录实际输入/输出 token、图片请求次数和上下文重传；不知道的字段为 null |

先用少量代表性样本排除明显无收益的路线，再用独立保留样本验证；阈值在正式对照前固定。接入条件是定位有稳定收益、误选没有明显恶化、端到端延迟可接受；小样本零误选不能当成安全证明。省 token 需单独用测量证明，不能把编号更短直接等同于整体更省。

阶段 A/B 均通过后，才安排受控动作验收，并经现有授权与执行器完成。最终可作为可关闭的定位方法接入，保留第一条线作为对照和回退配置。回退只影响未来规划选择，不重试未知结果的已发动作。

## 10. 数据保留与实验产物

候选标签、OCR文字、编号图都可能包含屏幕隐私，继承原始截图的授权范围与保留期限；图片可本地读取不代表自动获准发送给远程模型。不得把候选全文默认写进长期记忆或一般日志。

建议将未来实验集中放在独立的 grounding 实验结果目录，目录名在启动时按现有习惯确定。保存最小配置、版本、指标和失败样例引用。临时标注图/附件索引随源证据清理；源图删除或撤销使用后，相关候选表和缓存失效，不靠残留派生图继续使用。

实验结束统一写一次阶段记录；过程中保留必要机器证据，避免逐步生成大量叙述日志。当前新增本文不产生截图、缓存、临时图或实验结果文件。
