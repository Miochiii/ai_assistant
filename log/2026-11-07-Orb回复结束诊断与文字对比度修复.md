# Orb 回复结束诊断与文字对比度修复

## 用户现象与可确认的原因

用户请求“你能点击一下桌面上 deepseekharness 的插件按钮吗”，面板返回“回复未完成，请重试。陪伴模型回复未正常结束”。同时浅色背景上的助手文字为白色。

白字原因已确认：项目固定了浅色渐变，Orb shell 却通过 prefers-color-scheme 跟随 Windows 深色主题，造成文字 token 与背景不一致。此前发送 appearance.theme 并不能覆盖 shell 的系统主题监听。

模型错误来自 `companion-stream.js`：任何 finish.reason.kind 不等于 stop 的情况都被替换为同一句错误，原始原因没有保存。本次历史记录无法区分究竟是输出截断还是工具调用结束，不能把猜测写成已确认根因。

本机 Harness 适配器源码明确映射：end_turn/stop_sequence → stop，max_tokens → max-tokens，tool_use → tool-calls。此前每次输出上限仅 512 token。本轮没有重发用户的付费模型请求。

## 修改

- `orb-helper.cjs`：独立 helper 固定 nativeTheme.themeSource=light，与浅色背景一致。
- `vendor/orb/assets/assistant.css`：回复、正文和输入主色设为黑色，次级文字使用深灰；兼容深色属性残留，避免黑白 token 反转。
- `companion-stream.js`：输出上限从 512 调到 2048，仍关闭思考、工具列表仍为空。正常结束才返回正文；截断、意外工具请求、未知结束和缺少结束事件使用独立错误码。没有自动重试或把半段正文当成功。
- 同文件角色提示明确面板本轮没有动作工具；执行请求使用“交给主会话：任务”，看屏指导使用“教我……”。本次没有把 Orb 独立自动执行器接入面板。
- `resident-host.js`：结构化错误直接显示对应说明，不再对所有情况都建议重试；outbox 保存 error_code 和 finish_reason，不保存模型部分正文。

输出上限增大是针对已发现的配置瓶颈，不代表已证明原失败一定由 512 token 截断引起。若再次失败，应依据新错误码判断，不能继续盲目增加限制或开放执行权限。

## 验证和使用

12 项模型/图片/步骤验证单测通过；独立 Electron smoke 验证实际 DOM 计算颜色为 rgb(0,0,0)，以及展开、消息收发、隐藏恢复。原生 Harness 离线检查通过 29 次本地 SSE 请求，覆盖 max_tokens/tool_use 分类、图片传输、主会话隔离和失败后不写入短历史。另复查 Host 生命周期测试。

重启 Harness 后执行 `/assistant-open` 加载全部更新。单独关闭再打开球能刷新 UI，但主进程模型代码仍需 Harness 重启。验证脚本自动清理自己的临时目录；没有删除用户当前会话或消息记录。
