# Orb 干净会话准备与隔离验证

承接本日接口审计。新增 `plugins/dsh-orb-memory/clean-session.js` 和 6 项测试：仅在旧会话空闲、无排队消息、后台明确 clear、记忆版本一致时准备全新无历史会话。状态变化/取消释放准备结果，不取消旧任务，不改变 UI 绑定。

新增 `scripts/check_orb_clean_session.mjs`：当前安装 SDK 的 4 次假模型请求证明，新会话及从其日志恢复的会话不包含旧记忆、工具结果及派生回答；旧 caller 的 pre-step 门禁阻止迟到后台通知再次触发模型/工具。结果 `results/memory/orb-clean-session-20261110.json`。此门禁尚未持久化；没有真实 Orb UI 或磁盘 persistence 验收。

发现 Orb 私有 newSession/adopt 未暴露独立扩展入口，remember 写盘失败仍返回成功；code_agent 完成通知仍定向旧 caller。不能仅创建新会话或直接改 sessionFile 就宣称安全切换。

下一步在开发副本实现小型版本化 Orb host 服务，覆盖绑定事务、输入冻结、持久退休门禁和恢复/降级。接口与证据边界见 `docs/orb_memory_cutover.md`。不直接改已安装包、不恢复旧指导任务。本轮没有修改正式记忆库、C 盘配置或启动/关闭用户应用。
