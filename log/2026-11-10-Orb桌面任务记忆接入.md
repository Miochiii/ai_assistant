# Orb 桌面任务记忆接入

用户已验收 `查记忆：星桥` 和自然提问“我用什么写 Python”正确返回 PyCharm，并授权继续接入桌面操作任务。修改直接位于已被 C 盘 DSH profile 链接加载的 E 盘开发目录，开发包更新为 `0.2.1-mio-dev.4`；未退出用户正在运行的 DSH。

## 行为

- 原 Orb 提交任务前检索当前有效记忆，限定原项目和用户作用域，最多五条、6000 字符。原任务文本、权限配置和审批链保持原逻辑。无相关结果时继续正常任务。
- 记忆作为 runtime context 数据，明确不代表指令或操作授权，当前明确要求优先。调用原生模型与工具执行器，不增加可用工具或权限。不另发付费规划请求。
- `runtime/memory/orb-task-exposures.json` 在首次启用前显式初始化。每个会话使用记忆前先原子保存所用版本；启动获取状态文件和 Orb 绑定文件两把进程锁。状态读取/写入异常不放行相关操作，运行时不会把缺失账本自动当作空记录重建。
- 每个模型步骤、实际模型请求、流片段、工具 dispatch 前核对当前版本。最后一个检查发生在工具审批之后。失效后阻止新的调用，但不撤回已经执行或已经进入工具内部的动作。
- 暴露于失效记忆的会话，在下一次空闲的用户任务到来时创建干净会话。先持久标记旧会话退出使用，再原子写绑定并更新 UI/屏幕所有者；只带入这次用户请求，不复制消息、摘要、工具结果或附件。旧历史仍保留。
- 子任务通过 SDK `parentSession` 和 Orb registry 的调用者关联继承门禁，并持久记录其暴露。已退出使用的旧会话的迟到后台通知无法唤醒旧模型/工具操作。仍有未结束或状态未知的后台任务时不自动切换。
- 切换涉及未结束圈选/问答时提示结束后重发，不把截图悄悄转给新会话。用户新输入、停止、切换聊天会取消未提交的检索；聊天选择与绑定更新串行执行，避免覆盖用户的选择。
- `关闭自动记忆` 同时停止新任务检索；旧历史的失效门禁继续生效。状态新增“操作任务上下文注入：开启/关闭/服务异常”。

## 验证

22 项 Node 回归测试通过，包括原显式记忆和自然问答，以及新任务检索、取消、磁盘读写失败、版本切换、原任务保留、圈选和后台工作拒绝、状态校验、用户切换聊天时的写入竞态。命令：

```
node --test --test-isolation=none tests/test_orb_task_memory.mjs tests/test_orb_memory_recall.mjs tests/test_orb_memory_service.mjs tests/test_orb_memory_bridge.mjs
```

`scripts/check_orb_task_native.mjs` 使用已安装 DSH SDK、真实原生 agent loop / tool executor / 持久状态，模拟模型、记忆与工具。验证任务收到记忆并选择 PyCharm、关闭后干净会话不含旧记忆、旧历史重启后仍拒绝、子会话拒绝、审批期间与模型生成期间版本变化阻止工具执行。报告：`results/memory/orb-task-native.json`。未执行桌面动作、无网络或付费模型请求。

`scripts/check_orb_memory_recall.mjs` 使用临时 SQLite、真实跨日提交和本地检索模型，额外验证“帮我打开 Python 开发工具”语义检索返回 PyCharm，任务入口返回有效版本及记忆。报告：`results/memory/orb-natural-recall-smoke.json`。没有读取正式记忆数据库作为测试数据。

SDK 测试仍使用模拟 Orb UI，不能代替用户的真实桌面验收。此前 PyCharm 自然问答的真实验收已经通过，不代表本轮操作路径也已验收。

## 用户验收

1. 完全退出并重开 DSH，使用“Orb 开发版 · Mio”。
2. 输入 `自动记忆状态`，应看到“操作任务上下文注入：开启”。
3. 新建会话，直接输入 `帮我打开 Python 开发工具`，不要在任务文字里指定 PyCharm。预期按有效偏好选择 PyCharm，并按现有权限执行打开。
4. 记忆发生变更后再次发任务，会提示切到新会话；不要把该提示误当作历史丢失。旧历史不会删除。

已有有效记忆的自然召回与操作接入，以及新偏好的采集/跨日整理，是不同验收项。新偏好应在下一自然日整理后再验证；本轮不绕过跨日规则、不把旧便笺自动迁入召回、不自动确认候选。

## 维护边界

本轮启用 `taskMemory` 路径，原实验性 `memoryCutover` 配置保持关闭，避免两套绑定事务同时接管。已经使用过任务记忆后，不应通过删除暴露账本或移除所有门禁来“修复”；正常关闭使用用户命令，保留旧会话失效检查。后台任务/圈选仍有未决状态时优先提示，而非静默重放可能已经执行的任务。
