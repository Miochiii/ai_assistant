## 1. 必须实现的产品目标与本轮决策

助手应在用户连续使用后逐渐理解其偏好、长期事项、项目背景和操作经验。用户不应该每次换会话都重新介绍自己，也不应该只能靠逐条输入“记住”维持长期记忆。

本轮明确三项决策：

1. **直接复用成熟 RAG 的检索核心和既有模型资产**，不再另建一套功能相同的检索框架。记忆核心仍负责来源、作用域、版本和删除；RAG 是可重建的检索投影。
2. **每日自动整理、筛选、自动加入长期记忆是正式目标与验收项**。满足自动采纳规则的条目由可信 Host 入库，不逐条要求人工确认。“每天只生成候选清单，全部等待人工确认”不算完成。
3. **迁移变点检测的方法与可解释告警机制**，用于发现记忆检索或使用质量下降，提示诊断、整理、重新抽取或索引重建。报警本身不授权删除原始记忆。

用户当前已经明确要求设计自动入库。实施时可以据此落实约定范围，不重复询问每条普通记忆。需要把采集范围、保留策略、自动采纳规则和关闭入口做成可查看的设置；不得将这一目标扩展成收集所有历史聊天、屏幕隐私或任意软件内容的授权。

本文更新过去“只有显式记住／候选必须全部人工确认”的最终产品限制，但不描述当前 v1 已具备自动采纳。现有 v1 规则在新 Host 路径验收前继续生效。

### 2.1 直接接现有 HTTP 服务存在的具体问题

- `SearchReq` 没有逐请求的记忆作用域/索引代次参数。`search_kb` 依赖当前激活语料，`_state` 缓存也由服务管理。不能在共享服务中“切到助手记忆库→搜索→切回论文库”，这会与原工作台并发冲突。
- `normalize_filters` 只接受 year_min/year_max/authors/methods/tasks。直接传 user_id、project_id、active 等字段会被丢弃，**不能用它实施记忆隔离或有效性筛选**。
- `_filter_mask` 还可能读取当前论文语料的 MySQL 镜像。这条路径不应参与记忆检索。
- Qdrant 本地模式同一存储目录只允许一个客户端实例。两个服务不能同时打开原论文向量目录。
- `_build_vector` 会在探测锁后清理所指定向量目录再建库。记忆适配器必须始终提供经过路径校验的新代次目录，禁止传默认路径或原论文目录。
- embedding 与 reranker 加载函数目前硬编码 CUDA，并经过 ModelScope 加载路径。CPU 切换、纯离线加载、共享模型进程并不是现成能力。
- 中文分词有论文/金融词典来源。初版可复用分词逻辑，但记忆词典需独立，不能修改原论文词典以适配聊天。
- `KnowledgeBase.save` 使用 (source,text) 去重，不能表达记忆版本、撤销和自动采纳权限；不能代替现有 MemoryGateway。

## 3. 部署决定：复用算法与资产，分开服务和数据

第一版新增 **Memory RAG sidecar**，代码和配置放在助手项目中，通过本地 RPC 或仅监听 loopback 的私有端口供 Host 调用。

```text
Harness / Orb 面板
       │ 已授权的对话事件、当前问题
       ▼
助手 Memory Host
  ├─ 事件账本 + SQLite 权威记忆 + 版本/撤销/删除
  ├─ 每日整理 worker（无桌面动作工具）
  ├─ 当前请求的记忆选择与上下文失效处理
  └─ Memory RAG sidecar
        ├─ 复用原 RAG 检索核心、模型资产
        ├─ 独立 BM25 + Qdrant 数据目录/代次
        └─ 记忆质量指标与变点监控

原论文 RAG 工作台及其语料目录继续独立运行
```

优先以适配器调用固定版本的原检索类，显式指定数据路径并覆盖记忆专用筛选。需要改造模型加载、评分结果或词典路径时，将最小必要模块以带来源/hash 的兼容副本放入助手项目；不要通过运行时全局 monkey patch 改动原服务，也不要在成熟 RAG 主目录中顺手改接口。

RAG 依赖与助手 Python 3.14 环境分开。先核实原 RAG 实际解释器及已装依赖，再用已有环境启动 sidecar；不把全部 RAG 依赖安装进助手 `.venv`，不升级原 RAG 环境，不安装 CUDA。已有可工作的 CUDA 运行环境可以复用，但多进程可能重复占用显存，必须测量；若资源不足，排队或降级到明确标识的关键词检索。CPU/量化后端需要单独适配，不能声称目前已经支持。

加载时使用已存在的本地权重，缺失就报告缺失，不自动联网下载。服务不暴露原 `build/clear/switch/ask` 管理接口，不使用论文侧的 API 密钥执行记忆抽取。每日抽取使用助手现有模型服务及相应后台额度策略；本设计不启动新的付费实验。

## 4. 记忆数据组织与检索契约

维持三层，避免把所有对话直接塞入向量库：

1. **来源层**：被授权采集的消息/任务事件。记录 event_id、原角色、session/channel、实际时间、采集时间、版本或内容 hash。助手生成的话与用户原话分开保存。
2. **权威记忆层**：可复用的原子事实、偏好、画像字段、事件摘要和 checkpoint。保留来源关联、版本、更正、有效期、撤销及派生依赖。
3. **索引层**：供召回使用的短文本与向量。每块绑定 memory_id、memory_version/content_hash、scope、index_generation、embedding_profile。它是缓存投影，可以重建，不能自行生成事实或权限。

短事实一条一块，事件摘要按明确事件分块；暂不把论文默认 800 token 分块直接套在用户偏好上。长对话先按说话人、时间和话题整理，保留可回溯片段，不为每个短句都调用 embedding。

### 4.1 拟新增服务接口

- `health()`：后端版本、模型 profile、只读资源状态，不返回密钥。
- `search(scope_handle, query, kind_filter, as_of, limit, generation)`：返回稳定 ID、版本、排序及可得分项。
- `apply_projection(batch_id, scope_handle, mutations, source_revision)`：幂等投影更新，只有 Host 调用。
- `build_generation(scope_handle, snapshot_revision, manifest)`：生成新索引，不修改当前代次。
- `activate_generation(scope_handle, generation, expected_current, validated_revision)`：通过验收后原子切换。

scope_handle 由 Host 的用户/项目身份映射，不让模型提供任意文件路径或伪造作用域。初版按用户+项目物理分区，允许的个人全局偏好单独分区并单独授权；不能默认把工作项目记忆变成所有会话可见。

原检索结果主要是 `{index,text,metadata}`，index 只是代次内位置。适配器必须映射成稳定 memory_id；不能把数组下标当永久记忆 ID。分项分数和解释字段缺失时明确标为 unavailable，需要补充采集，禁止把排序序号冒充概率。

### 4.2 每轮如何使用

1. 明确字段（称呼、指导风格、指定任务 checkpoint）优先精确查询。
2. 需要往事/背景时，在允许的作用域进行 BM25 与向量候选召回，复用 RRF、reranker，MMR 作为可选去重复策略。
3. **候选进入模型重排或任何外发步骤前**，由 Host 核对来源授权、版本、撤销、有效期和依赖。索引快照之外的变更通过失效 ID/活动 ID 掩码及时同步。仅在最终答案前过滤不足以保护已撤销内容。
4. 如因失效过滤不足以凑满候选，可有界扩充召回；不得为了凑条数取消作用域或有效性条件。
5. 为本轮构造少量相关记忆包，默认建议最多 5 条、约 1500 token，均为待评估参数；保存本次 exposure 的 ID/版本和选择原因。
6. 发起请求前再次核对 revision。记忆包是参考数据，不是工具指令；不把检索包追加到主会话或永久短历史。

现有“查记忆”只直接展示结果，可继续保留。新增自动 recall 使用独立面板请求，不直接打开现有主会话的全局 auto_recall。助手回复可能复述旧记忆，因此更正/撤销后，命中过旧记忆的短历史也要失效；没有精细依赖时保守清空该面板短历史。不能声称 RAG 自动解决 Harness 历史残留。

## 5. 每日自动整理与自动入库——必须落地

### 5.1 采集范围与触发

在设置中启用“自动整理我的助手对话”后，对约定的助手面板/陪伴会话采集后续事件。用户可以暂停、排除会话，并通过“这段不要记忆”标记排除区间。其他 Harness 项目、QQ、浏览器、屏幕截图及历史会话回填都不是默认来源。

自动整理以用户本地日期（当前 Asia/Shanghai）和消息序号水位为准。建议每天本地空闲时运行一次，例如次日 02:00；这是建议配置，不是在本文创建定时任务。电脑关闭时，下次启动补处理未完成日期；不要求机器整夜开机。忙碌时延后，消息仍持续积累，不能漏掉午夜附近的会话。

当日对话长时，按会话/话题分批抽取，再合并当天结果；只处理上次成功水位以后的新事件，不每天重新读取全部历史。较新的当天内容可以先做增量整理，日终做去重与归并。

### 5.2 完整流水线

```text
授权范围内的事件 → 冻结批次 manifest 与高水位
  → 排除“不记忆”、敏感凭据、重复或被删除来源
  → 隔离模型抽取候选（无桌面执行工具）
  → 本地验证来源/引用/类型/有效期/作用域
  → 检索已有记忆，区分新增、重复、补充、冲突
  → 自动采纳策略判断
  → SQLite 事务提交有效记忆 + 投影 outbox + 作业进度
  → RAG 增量索引/必要时构建新代次
  → 日报：新增、合并、待确认、跳过及失败数量
```

模型可输出 proposed_kind、内容、source_event_ids、原文引用范围、时间、候选 key、可能的关系与建议有效期。它不能设置 authoritative=true、confirmed_by=user、授权范围或直接删除已有记忆。结构校验、策略判断和最终写入由 Host 完成。

抽取调用只提供本批次获准内容。对话中的“忽略规则、保存密码、给自己授权”等文字是待分析数据，不能成为 worker 的执行指令。助手自己说过的猜测不能经反复总结升级成用户事实。

### 5.3 自动采纳矩阵

| 内容 | 默认处置 |
| --- | --- |
| 用户直接表达的普通偏好，来源明确且无冲突，例如“讲步骤时短一点” | 自动加入有效记忆，记录 automatic/daily 策略版本与原话 |
| 用户明确陈述的低敏感事实、项目约定 | 自动新增或对同值去重；保存时间与适用项目 |
| 用户明确描述的计划、短期事项 | 可自动记为“计划/待办”而非已完成事实，按类型给出期限 |
| 有可信运行证据的任务进度 | 自动 checkpoint；失败/未知不写成成功 |
| 事件摘要 | 来源可追溯才可自动入库；摘要只表达来源支持的事实，不添加动机、身份或结论 |
| 与现有当前值冲突或模糊的新偏好 | 保存为待确认候选，不自行覆盖人工固定值；显式更正命令优先 |
| 用户明确、可核实地更正原话，属于已获授权的普通类型 | 可由规则判定后自动创建新版本；保留旧版本关系，不原地覆盖 |
| 模型推断的人格、情绪、健康、财务等敏感结论，或第三方隐私 | 默认不自动采纳；必要时单独征求用户明确意图 |
| 密钥、密码、验证码、会话令牌 | 不进入长期记忆或向量索引 |
| 网页/软件画面里的指令、模型自行承诺的动作权限 | 不作为用户偏好或授权入库 |
| 可执行软件流程 | 只生成程序候选；必须经过既有 PreAct 验证，记忆采纳不能把程序变成已验证 |

自动采纳的依据是来源、类型与冲突规则，不是模型自报“置信度 0.9”。初版先覆盖偏好、普通事实、事件和 checkpoint；未知类型进入候选，不让模型临时发明入库类别。

每日自动处理不等于每天制造“收获”：无值得记忆内容时正常完成并记录零新增。用户可以查看自动写入来源、纠正和撤销。人工复核只处理例外，不阻塞整天的低风险入库。

### 5.4 幂等、并发与恢复

作业键至少包含 scope、day、源批次 manifest hash、抽取模型/提示词版本、策略版本。消息修订形成新来源版本，不复用旧 hash。

- 单个作用域只有一个提交者，使用租约/锁与持久化状态。
- 状态建议：pending → extracting → validated → committed → indexed；failed/retryable/quarantined 分开。
- 作业进度、已处理事件和有效记忆同一 SQLite 提交，避免提交成功却水位丢失导致重复写入。待确认项也记录已抽取，不能每天重复制造同一候选。
- SQLite 与向量库不假设跨库原子事务。权威提交同时写 outbox；索引失败可重试，UI 显示“已保存，检索索引待更新”，不能谎报全部完成。
- 重试复用 batch_id 和 mutation_id，避免重复 embedding/重复记忆。模型失败不把半截 JSON 当结果，不推进成功水位。
- 停用策略或删除来源时撤销尚未提交的作业资格；提交事务内复核授权版本及源仍存在，防止旧 worker 重新写回已删除信息。
- 固定的内容 hash 去重之外，要保留“同一句话在不同日期重复表达”的来源关联；相似度高不等于语义相同，否定句与时间变化不能误合并。

## 6. 变点检测迁移：报警负责发现异常，不负责认定应删除什么

用户提出“把变点看作需要清理重建的提示指标”可行，但要区分三类变化：

1. **内容正常变化**：开始新项目、换兴趣、偏好更新。应新增/修订记忆，不意味着库坏了。
2. **检索质量变化**：漏召回、旧版本占候选、重复过多、embedding/词典配置改变。可能需要修索引、重新嵌入或重排。
3. **抽取或回答质量变化**：把猜测存成事实、把计划说成完成、模型忽略检索证据。应修抽取策略/提示词/上下文；单纯重建向量不会修好错误正文。

### 6.1 记忆专用指标

| 指标 | 可用证据 | 用途 |
| --- | --- | --- |
| Recall@K/已知相关条目漏召回率 | 有标注的固定探针和人工纠正实例 | 检索退化 |
| 候选中撤销/过期/旧版本比例 | SQLite 状态与索引版本对照 | 索引滞后；失效结果不得继续注入 |
| 重复与冲突率 | key/版本规则及可核实来源 | 整理或抽取退化 |
| 自动入库被用户撤回/更正比例 | 自动采纳批次与后续反馈 | 质量线索；没有反馈不算正确样本 |
| 来源支持率/证据矛盾 | 原始片段与独立标注，自动评价作为弱证据另列 | 错误抽取或回答 |
| 索引延迟、失败率、分区计数/hash 不一致 | 系统记录 | 工程完整性告警，可直接触发修复 |
| 查询分布、空召回率、相似度分布 | 请求统计，无内容真值保证 | 辅助漂移线索，不能单独等同记忆错误 |

不把模型自评、向量相似度、未被投诉当成客观准确率。unknown、证据不足、流程失败分别计数，不记为 0 损失，也不混进已评价分母。

分层至少区分：偏好读取、事件回忆、时间查询、知识更新、checkpoint。模型/提示词、embedding、分词、reranker、索引代次和评分协议都绑定 monitor profile。任务组成或配置改变时新建 epoch，不让新任务的难度变化伪装成旧任务质量下降。

原条件 CUSUM 的论文题型、正常风险和阈值都不能照搬。用新的正常记忆样本拟合，在独立留出流和任务比例变化流评估误报，再用受控故障评估检出延迟；测试例不能全由被评估的同一抽取模型自己出题自己判。

`edetector.py` 的理论声明有条件前提；迁移到用户聊天和模型评判信号后不能直接宣称同样的误报保证。数据不够时只显示“未校准趋势提示”，禁止包装成已验证在线报警。

### 6.2 报警后的动作

第一阶段只产生可解释诊断：哪个分层、哪个指标、与哪个基线相比、从何时开始、受影响哪些样本、unknown 占比及建议动作。

工程完整性错误（缺索引、计数/hash 错、版本不兼容）可以直接排队重建派生索引，不必等待统计变点。统计报警先定位原因：检索问题再重建索引，来源错误进入重新抽取/更正，正常偏好变化走版本更新。

后续允许自动重建索引，但限定为以下条件同时成立：允许的记忆分区、数据路径校验通过、索引问题有证据、已有构建授权、资源满足、新代次离线验收通过。全量删除权威库、清空原文、删除备份不属于自动报警动作。

## 7. 整理、重建与删除是不同操作

- **整理**：合并重复表达、整理来源、形成事件摘要、调整有效期。新摘要是派生记忆，继承来源授权和依赖；摘要不自动抹去原记录。
- **索引重建**：从仍有效的权威记忆重新构造 BM25/向量，允许自动化。
- **重新抽取**：从仍获准保留的原始对话重新生成候选，重新经过采纳规则。不能用被删除的原文或旧摘要偷偷恢复记忆。
- **遗忘/删除**：按用户要求或明确保留策略处理正文、来源、派生摘要、向量、缓存、待处理作业和 exposure。索引轮换或归档不是遗忘。

重建使用新目录：冻结 SQLite revision → 导出有效记忆 manifest → 构建新代次 → 校验作用域/数量/hash/模型 profile/检索样例 → 补齐构建期间增量 → 原子切换 active pointer。

切换期间保留旧代次用于工程回滚，但每次检索仍按当前撤销/删除账本过滤。**回滚不能让已删除记忆复活。**涉及用户删除时，旧代次中的对应数据也在删除覆盖范围内；未完成清理的副本必须禁止服务并明确标记待擦除。

本机 Qdrant 由单进程持有目录；并发请求持有代次租约，旧客户端只在读者释放后关闭。重建失败继续使用通过验证的旧索引，或降级到当前有效记忆的关键词/精确查询，不能让维护导致助手无法聊天。

“到期不再召回”与“删除磁盘正文”分别设置。建议初始原始对话保留 30 天、临时事件按类型设置期限、长期偏好保留到更正/撤销；这些是待实施的产品默认建议，不是本轮已经生效的设置。备份、附件和本地诊断另有保留范围，删除报告必须如实列出未覆盖副本。

## 8. 实施顺序与验收门槛

| 阶段 | 具体工作 | 完成条件 |
| --- | --- | --- |
| M0 复用接缝 | 核实原解释器/模型资产，建立独立 sidecar；禁止共享切库和默认索引路径 | 纯离线 fixture 能检索；原论文服务/文件不变，无模型自动下载 |
| M1 语义记忆 | 将已确认记忆投影到独立索引，接入面板本轮检索与 exposure | 换种说法可找回；更正/撤销及时生效；跨用户/项目零泄漏；可降级 |
| M2 对话采集 | 加入会话采集策略、事件账本、水位、排除入口和作业队列 | 正常/重启/跨日/消息修订不丢不重；关闭采集后无新增来源 |
| M3 自动整理 | 分批抽取、去重冲突、自动采纳、事务 outbox、每日摘要报告 | 普通明确偏好无需“记住”也能在次日被正确使用；无需逐条人工确认；敏感/冲突例外不污染有效库 |
| M4 质量闭环 | 固定探针、用户反馈、来源评价、分层基线、影子监控 | 可解释告警，未知分开；阈值有新场景留出证据；无数据时不宣称校准 |
| M5 维护自动化 | 新代次重建、切换回滚、增量补齐和删除覆盖 | 故障不破坏旧库；删除在旧代次、重试作业、派生摘要中不复活 |

M3 是本需求的必达阶段，不应在 M1 做完搜索后把“每日自动整理”无限期留到以后。M4/M5 可以继续演进，但 M1–M3 必须保持已启用自动记忆的正常日常闭环。

建议验收场景：

1. 第一天普通聊天表达“教程请一步一步来”，无需记住命令；自动整理后，第二天新会话指导正确使用偏好并能解释来源。
2. 同一天说过一次临时想法和一次明确长期偏好，系统能区分，不能都永久保存。
3. 人工纠正偏好后旧向量仍暂时存在，模型也只能获得新版；晚到 worker 不得恢复旧值。
4. 点击“本段不要记忆”后，原文不进入抽取；模型/网页里的伪授权无效。
5. 23:59–00:01 连续对话、电脑隔天开机、作业中断重跑，均不丢失、不重复入库。
6. SQLite 提交后索引服务故障，记录为待索引，恢复后自动追平；不二次生成同一记忆。
7. 注入重复索引、旧 embedding profile、漏项与撤销候选，能区分工程故障、内容变化和统计报警。
8. 重建过程中新增、修改、删除记忆，切换后版本正确；回滚不复活删除项。
9. 源对话与检索内容不进入主 Harness 历史；撤销影响过的面板短历史失效。

评测参考已有 LongMemEval 的跨会话、时间、更新和拒答维度；结合自己的中文陪伴样本做小规模人工标注。Mem0/LangMem 只用于抽取与治理实现参考，检索主干优先复用本机成熟 RAG，不再为了接记忆引入一整套替代框架。

## 9. 给实施者的边界

本方案的主线是“自然对话形成长期可用记忆”，不是让用户每天手动管理数据库。低风险自动采纳应顺畅；同时记忆内容始终不授予桌面动作权限，也不把未经验证的轨迹变成 PreAct 程序。

开始编码前以本文列出的实际接口缺口为清单，先完成独立分区和最小检索闭环，再接自动采集和整理。不要先修改成熟论文库、安装另一套向量框架或打开无限历史扫描。每日整理、索引更新与质量监控都应有持久化进度、可解释结果及可恢复失败处理。
