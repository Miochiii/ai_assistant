# 点击命中反馈（click hit info + expect 校验）

更新日期：2026-11-17。来源：Orb 的反馈总结（六类"看不清"），按性价比先做第 1、3 条。
本文件记录**改了什么、怎么验、有什么局限**；"变化判定 changed" 留到下一轮。

## 1. 为什么要改

36 条真实点击日志（QQ 发消息 / 资源管理器 / Word 删符号 / 改缩进）里的分布：

| 现象 | 次数 | 性质 |
|---|---|---|
| 坐标映射错误 | 0 | 已排除 |
| 多步 GUI 流程 | 1 次完整成功（段落对话框） | 可行 |
| **点了没反馈 → 反复点** | ~15 | 缺"变化判定" |
| **对控件位置估计偏差** | 4（QQ 表情按钮 vs 输入框） | 缺"命中信息" |

而且日志只记了"点在哪"，**没记"点到了什么"** —— 点空和点中在数据里长得一样。这次的改动就是补这个。

## 2. 改了什么

### 2.1 原生层：`describeWindow(hwnd)`

`dist/computer-use/windows-native-B1bSWITt.js` 新增一个只读 op，返回：

```js
{ hwnd, class, title, pid, exe, foreground }
```

用的是已有绑定：`GetClassNameW` / `GetWindowTextW` / `GetWindowThreadProcessId` / `QueryFullProcessImageNameW` / `GetForegroundWindow`。零新依赖、微秒级。

### 2.2 平台后端：`describePoint(x, y)`

`dist/computer-use/lasso-BVa38J49.js` 的 Windows 后端新增：`WindowFromPoint` → `GetAncestor(GA_ROOT)` → `describeWindow`。
**返回的是顶层窗口**（不是 UIA 元素）—— 见 §5 局限。

### 2.3 工具层：`click` 的返回与参数

`dist/computer-use/index.js`：

1. 包装器转发 `describePoint`；
2. `click` 新增可选参数 `expect`（字符串，大小写不敏感的包含匹配：窗口类名 / 标题 / exe）；
3. 点击前算一次命中，点击后再算一次；
4. 结果里多三个字段：`hitBefore`、`hitAfter`、`activated`、`dpi`；
5. 结果文案多一句：

```
Clicked screen 0 at [500, 500] (left, count 1). Coordinates remain 0–1000.
Hit: QQ · Chrome_WidgetWin_1 · "QQ". This click brought that window to the front
(foreground changed); it may not have hit a control — verify before retrying. DPI: 150%.
```

`expect` 不匹配时**拒点**（不发送任何输入），报错里带实际命中的是什么：

```
computer-use: click refused — expected "段落" but that point is over
WINWORD · OpusApp · "文档1" at [1206, 702]. Nothing was clicked; re-observe and aim again.
```

非 Windows 平台拿不到命中信息时，这几个字段**不输出**（避免模型看到 "unknown" 去猜）。

## 3. 怎么验

1. 重启 DSH（改的是宿主侧的 computer-use 插件代码）；
2. 让模型点任意一个控件，看返回里有没有 `Hit: ...`；
3. 试一次"期望校验"：`click(position, expect:"不存在的词")` 应该被拒绝并报出实际窗口。

## 4. 回退

- 想看原样输出：`expect` 不传，`hitBefore/hitAfter` 只是多打的字，不影响点击；
- 想彻底关：把 `index.js` 里 `const before = await describeAt(...)` 两行与返回里的 `...(before === void 0 ? {} : {...})` 删掉即可；
- 原生层改动是**纯增量**（新增一个 op），删掉不影响既有方法。

## 5. 局限（必须说清）

1. **只到窗口级，不到 UIA 控件级**。Orb 要的"UIA 控件类型+名称"这次**没做**：那需要挂 UI Automation provider，成本高一个量级。
2. 好处是：**传统弹出菜单是独立窗口**（类名 `#32768`），所以"点在菜单上"还是"点在文档上"现在能分出来 —— 这已经能覆盖菜单误点的一大半。
3. `activated: true` 的含义是"这次点击改变了前台窗口"，可能是激活窗口、也可能只是切到另一个窗口；模型要结合 `hitBefore/hitAfter` 判断，不能单看这一个布尔值。

## 6.1 `.26`：点后变化判定 `changed`

### 怎么做的

1. **原生层** `captureRoiRaw(bounds)`：`BitBlt + GetDIBits` 取一块区域的原始 BGRA（自上而下、**不画光标**），不编码 PNG —— 所以两帧逐字节可比，也不需要 JS 解 PNG；
2. **平台后端** `captureRoi(rect)`：转发到上面那个；
3. **工具层**：点击前抓一帧，点击并等 `postActionWaitMs` 后（跟返回截图同一时刻）再抓一帧，逐像素比 RGB，单通道差 > 24 才算"变了"；变化像素占比 > **0.3%** 判定 `changed: true`。

### 参数

| 常量 | 值 | 说明 |
|---|---|---|
| `CLICK_ROI_HALF_WIDTH` / `HEIGHT` | 110 / 80 | 点击点周围 220×160，贴屏幕边时自动收缩 |
| `CLICK_DIFF_CHANNEL` | 24 | 单通道差阈值（忽略抗锯齿/温和渐变） |
| `CLICK_CHANGED_RATIO` | 0.003 | 变化占比阈值；光标闪烁约 0.1%，够不着 |

### 返回值与文案

```json
{"changed": true, "changedRatio": 0.0231}
```

```
… Hit: QQ · Chrome_WidgetWin_1 · "QQ". DPI: 150%.
Screen nearby changed (2.3% of the area) — the click had an effect.
```

没变时：

```
… Screen nearby did NOT change — this click may have hit empty space or a
non-interactive area; re-observe before clicking the same point again.
```

### 单测与已知局限

已测：完全相同 → 0 / 四分之一变 → 25% / 单像素 → 低于阈值判 false / 尺寸不一致与缺帧 → 不输出字段（保持原文案）。

局限：
1. **只看点击点周围 220×160** —— 点击导致的弹窗若开在别处，会误判成"没变"；
2. 界面动画慢于 `postActionWaitMs`（默认 300ms）时也可能误判；
3. 判定为"变了"不等于"做对了"（可能只是高亮/焦点环）—— 它只回答"这一下有没有起作用"。

## 7. `.27`：UI Automation —— 控件级命中 + 按名字点击

### 探测结论（Word 实测，2026-11-17）

| 指标 | 结果 |
|---|---|
| UIA 坐标系 | **物理像素**，root `2582×1462 @ -11,-11` == 截图 bounds（Win32 GetWindowRect 在 DPI 不感知进程里给 1721×975，别用那个） |
| `ElementFromPoint(x,y)` | **1 ms** |
| `FindFirst(name="增大字体")` | **35–79 ms**，rect `(412,135,36,36)` → 中心 `(430,153)` |
| 整树遍历（209 个元素） | 84–457 ms（视文档状态） |
| 命中校验 | 裁图放大确认：A⁺ 按钮正好在 (412,135)，与 UIA 完全一致 |

同一次测试里模型在 (457,154) 点的是**缩小字体**、在 (416,154) 才点到增大字体 —— 有控件级命中信息才能当场发现"点反了"。

### 实现

1. `uia-helper.ps1`：常驻 PowerShell（`-STA`），stdin/stdout 走 **JSON 行协议**，支持 `ping` / `elementAt` / `find`；
   `find` 失败时回传附近 40 个可点名字，供模型改口。
2. `uia-bridge.js`：Node 侧懒启动 + 请求/响应配对 + 1.5s 超时 + 超时杀进程重启 + 父进程退出自动清理。
   **任何异常都只让 UIA 这一路失效，不抛给点击路径**。
3. `click`：
   - 命中信息优先取 UIA，格式变成 `Button · 增大字体 (in 文档1 - Word)`；
   - 新增 `name` 参数：按名字找到元素矩形 → 点中心（`position` 变成可选，二选一）；
   - 找不到时**拒点**并列出可用名字。

### 代价与局限

- 常驻一个 PowerShell 进程（约 30–40MB），随宿主退出；
- 只在 Windows 生效；Chromium 系（QQ/微信/VS Code）的 UIA 树可能很薄，**需要逐个探测**；
- 元素名是**本地化**的（"增大字体" / "Increase Font Size"），跨语言要换名字；同名元素可能有多个（取第一个）。

### 下一步

- **Excel 适配**：用同一个探测脚本 `tools/location-test/uia-probe.ps1 -ProcessName EXCEL` 看按钮命名与耗时；
- Chromium 系探测（QQ / VS Code）决定要不要为它们单独做；
- 若 UIA 名字不稳定，再考虑"列出当前窗口可点名字"的独立工具（模型先看名字再点）。

## 9. 各软件 UIA 覆盖实测（2026-11-18，扩展依据）

统一用 `tools/location-test/uia-probe.ps1` 探；Chromium 应用要传 `-Hwnd`（它们有多个顶层窗口，`MainWindowHandle` 常常指向小弹窗）。

| 软件 | 内核 | 元素总数 | 有名字的可点元素 | 整树遍历 | 档位与可用性 |
|---|---|---|---|---|---|
| Word | 原生 | 209 | **83** | 84–457ms | A：功能区按钮全覆盖（"增大字体" rect 412,135,36,36） |
| Excel | 原生 | 1052 | **124** | 254ms | A：功能区全覆盖（"增大字号" rect 507,135,36,36）；字号/字体是 **Edit** 控件也能按名字点 |
| VS Code | Chromium | 315 | **68** | 53ms | A−：菜单栏/侧栏/终端/状态栏都有名字；编辑器正文是画布 |
| QQ | Chromium | 398 | **46** | 66ms | B+：发送/表情/文件/截图/语音消息等按钮都有名字；聊天区是 Pane（无名字） |
| 微信 | **Qt** | **1** | **0** | 10ms | **C**：完全不暴露 UIA，只能坐标 + `changed` |

关键认知：

1. **Chromium 系（VS Code / QQ / Edge）默认不建无障碍树，但只要有 UIA 客户端查询就会自动开启** —— "探测即开树"。
2. **Qt 应用（微信）没有这条路**，除非它自己编译了 accessibility 桥。备选是 OCR（`Windows.Media.Ocr`，未做原型）。
3. 名字是**本地化**的；同名元素真实存在（`更多`×4、`关闭`×2、`缩小`×2）。当前取第一个，模型点错时靠 `changed` 自我纠正（用户已确认先不做消歧）。
4. `changed` 的 ROI 是点击点周围 220×160；弹窗开在别处、或动画慢于 300ms 时可能误判"没变"。

## 10. `.29`：UIA 发现层（运行时自动探测，不再需要我先跑脚本）

目标：新软件不用人工探测，模型在任务里自己摸清"有哪些按钮"。

### 三层结构

| 层 | 做什么 | 开销 |
|---|---|---|
| 名字查找 | `click(name)` → `FindFirst(NameProperty)`，命中就点中心 | 35–79ms |
| 名字表缓存 | `list_controls` 一次遍历拿全量名字，按 **(app, hwnd)** 缓存 **10 分钟** | 首次 17–1480ms，命中 0ms |
| 能力表 | 每次遍历顺手记 `{app: {named, walkMs, tier, probedAt}}` 到 `~/.dsh/storages/uia-capabilities.json` | 一次写文件 |

缓存的是**名字**；坐标（矩形）每次重新查，因为窗口会动。

### `list_controls` 工具

```json
{"filter": "字号", "limit": 40, "screen_index": 0}
```

返回形如：

```
2 of 124 named controls in "EXCEL" tier A (walked 254ms):
- 增大字号 (Button) @ 507,135 36x36
- 字号 (Edit) @ 191,138 233x30
```

### 失败不再只是抛错

`click(name:"发送")` 在微信里会返回：

```
no element named "发送" in "Weixin". Nothing was clicked.
This app exposes no named controls (tier C (named 0, walked 10ms)), so
click-by-name cannot work here; use position with a screenshot instead.
```

模型据此**自己决定**：换名字（附候选）还是回退坐标点击。

### 实测（2026-11-19）

| 应用 | named | 首次遍历 | 缓存命中 | tier |
|---|---|---|---|---|
| DSH 自己的窗口（Electron 大树） | 270 | 1480ms | **0ms** | A |
| explorer（桌面窗口） | 0 | 18ms | 0ms | C |

顺带修掉两个 bug：

1. **虚拟化元素 ±∞ 矩形**会让 helper 抛 `无法将值"∞"转换为 System.Int32`，整次列举失败 → 改成安全转换（非法矩形返回空数组）；
2. **列出时对每个元素回溯 12 层找顶层窗口**，是 O(n×12) 次跨进程调用 → 列表路径改用轻量模式（不回溯），DSH 窗口从"超时"变成 1.5s。

## 11. `.30`：修 `list_controls`、名字三级匹配、探测别打断菜单

模型侧实测反馈的三条问题，逐条修。

### ① `list_controls` 报 `content.some is not a function`

`render` 返回的是**字符串**，而 DSH 的渲染管线要求 **blocks 数组**（内部会 `content.some(...)`）。
→ 改成 `render: (_args, value) => [{type: "text", text: value.text}]`。

同时发现 helper 本身也挂了：我给 `uia-helper.ps1` 加中文注释后，**Windows PowerShell 5.1 把无 BOM 的 UTF-8 当 ANSI 读**，
注释里的多字节字符把下一行吞掉，解析直接失败（脚本根本起不来）。
→ **helper 改成纯 ASCII**（注释用英文），并加了脚本级校验习惯。

### ② 名字必须写全后缀

Edge 的可访问名是 `设置及其他 (Alt+F)`。现在改成**三级匹配**：

1. 精确匹配 `Name`；
2. **去掉尾部 ` (Xxx)` 后缀**再比（`设置及其他` → 命中）；
3. 子串包含（`设置` → 命中）。

实测（Edge，未最小化时）：三种写法都命中同一元素 `Button · 设置及其他 (Alt+F)`。

### ③ 探测会把刚打开的菜单关掉

`click(name)` 失败时会遍历整棵树找候选 —— 这次遍历本身会打断瞬态 UI（Edge 的 ⋮ 菜单、Word 右键菜单）。
→ 失败时**不再现场遍历**：只读名字表缓存（`peekControls`），没有缓存就只报能力等级；
需要名字时让模型**显式**调 `list_controls`（它知道这一步有风险，可以选择不调）。

### 附带两项

- `list_controls` 每条现在带 **`center=x,y`**，可以"探一次 → 记住坐标 → 之后按坐标点"，彻底绕开探测打扰；
- 最小化窗口的 UIA 矩形是天文负值（实测 Edge `-31713,-31934`），helper 过滤掉；
  若元素找到但没有可用矩形，`click(name)` 会明确说"窗口可能最小化或在屏幕外"，而不是含糊地"没找到"。
