# Orb 悬浮球与视觉高亮接入

日期：2026-11-07。供 DeepSeek 接手阅读。

## 本次结果

默认 UI 已由自制 Tk 聊天面板换成 Orb 的 Electron 悬浮球。用户已确认悬浮球能够出现；另用独立离线夹具验证了页面加载、展开、输入提交、回复显示、截屏前隐藏确认和恢复显示。没有启动真实模型请求，也没有操作其他软件。

采用“复用 Orb 前端及坐标代码，适配现有 Host”的方式。保留现有隔离聊天、显式记忆、角色提示、任务状态机和动作授权体系。没有同时启动第二套 Orb agent/action loop，避免两套上下文、权限与执行器互相竞争。

## 代码入口

- `plugins/dsh-assistant-host/orb-helper.cjs`：Electron 主进程；适配本地 inbox/outbox，校验实例 ID，处理窗口几何、输入、停止、菜单、截图隐藏握手。
- `ui-process.js`：支持独立 Electron 可执行文件；保留旧 Python UI 启动能力。清除子进程继承的 ELECTRON_RUN_AS_NODE。
- `panel-session.js`：默认启动 Orb；会话绑定、截图隐藏、捕获队列、关闭清理和高亮解析。显式指定旧 Python panelPath 的测试仍可运行。
- `panel-model.js`：保留面板短上下文和显式记忆分流；指导模式获取当前图并上传为附件，同一请求输出文字和目标坐标。
- `visual-target.js`：解析 JSON，复用 Orb 坐标映射；结果不是完整控件边框，而是围绕模型目标中心的 36×36 物理像素指示框，边缘裁剪在截图范围内。
- `highlight-controller.js`：串行更新高亮进程，避免隐藏/显示竞争和重复启动；同一 highlight_id 不重复写入刷新寿命。
- `resident-host.js`：高亮到期自动清除；回复失败反馈到消息通道；新指导回复先清理旧高亮。
- `panel-guidance.js`：验证优先使用完整图片，附件建立后释放本轮本地截图文件。

## 指导路径

1. 用户在球的对话面板输入“教我……”或在指导中输入“下一步/继续”。
2. 隐藏旧高亮与当前悬浮球；等待隐藏确认后，MSS 捕获第 1 显示器。
3. 将原图附件和用户目标交给已有 Harness 模型服务的独立请求。附件服务若等比例缩放，归一化坐标仍映射回原图范围；这里没有使用变化区域缩略图做定位。
4. 模型返回 `{"text":"步骤说明","target":{"label":"目标","position":[500,500]}}`。看不到或有歧义时 `target:null`。
5. 使用本次图片的 bounds 转成物理坐标，再交给现有只读 overlay。不会自动点击或输入。
6. 图像超过 60 秒不再建立高亮；建立后的高亮 10 秒自动隐藏。重新指导会重新截图。

旧的文本猜测目标和把模型疑问句改写成肯定点击句的逻辑已从生产指导路径移除。旧 `[[HIGHLIGHT:...]]` 标记不能直接授权高亮。独立 `/assistant-highlight` 手动 OCR 命令保留，不是新的模型指导路径。

已对照官方 SHASUMS256.txt。安装位置：

`C:\Users\Mio\AppData\Local\DesktopAssistant\runtimes\electron-44.0.0`

工作区内的运行时受本机完整性标签影响启动失败；使用用户目录中的运行时后成功。没有修改项目 .venv 的完整性标签，没有安装 CUDA 或变动 RAG 环境。通用 Electron 和 Harness 自带可执行文件不能互换。

Harness 的现有插件依赖使用 link 指向本项目；重启 Harness 后执行 `/assistant-open` 即进入新 UI，不需要另外安装 Orb 插件。打开本身不调用模型；面板普通聊天与指导沿用现有模型服务。

- 悬停展开，点击球固定，拖动移动/吸边。
- Enter 发送，Shift+Enter 换行。
- 右键可检查当前步骤、结束指导、设置/查询/停用指导偏好、关闭助手。
- 普通聊天、`记住，内容`、`查记忆：关键词`、`交给主会话：任务` 保留原有分流。
- UI 最多保留 100 条渲染消息；模型短上下文仍为最多四组问答且不超过 8192 UTF-8 字节。渲染缓存上限不等于长期记忆保留策略。

1. `node scripts/preview_orb.mjs --smoke`：独立 Electron 页面实际加载并经过 IPC/Host 文件通道回显，验证截图隐藏握手与恢复。夹具只用固定本地回复，自动关闭并删除临时目录。
2. 相关单测 25 项通过：模型隔离、图像附件、坐标边界/负坐标、无效坐标拒绝、任务生命周期、取消后迟到回复、串行高亮与自动过期等。
3. `scripts/check_companion_isolation.mjs`：通过本机 Harness 原生 AgentLoop、附件服务和 DeepSeek 适配器；传输替换为本地 SSE。20 次看屏、1 次聊天、3 次偏好版本、1 次视觉指导、2 次主会话共 27 次模拟请求，证明视觉请求实际带图且主会话没有混入陪伴/指导内容。

## 明确的剩余边界

- 本轮没有做真实模型的端到端定位验收，不能把离线坐标换算正确等同于模型目标识别准确。
- 指导目前捕获第 1 显示器；尚未自动选择鼠标所在屏或目标窗口。模型期间移动窗口仍可能让高亮过时。10 秒寿命只是限制展示时间，不是执行前校验；高亮不能作为点击权限或动作完成证明。
- 已有后台 `/assistant-model-watch` 使用另一条截图适配器，目前尚未共享悬浮球隐藏握手，可能拍入助手自身。不要声称全部观察入口已排除助手 UI；后续可在统一观察层解决自反馈。
- 截图本地中转文件在附件建立后释放；Harness 附件库、已有收发文件和诊断记录按各自保留规则处理。没有通过清空短历史宣称删除全部数据。
- 本次复用没有启用 Orb 的独立主会话浏览/权限切换/自动执行链路。真实键鼠动作继续经过已有统一动作协议和 Medium 执行器；不能从 UI IPC 直接绕开。
- 悬浮球关闭不等于另外启动的后台观察自动停止。停止观察继续使用 `/assistant-model-stop`；需要将两者合并为同一生命周期时应显式处理已有 watch 实例。

后续优先验收：重启后聊天能回到球的面板；“教我……”确实理解当前软件界面并显示目标；改动窗口位置后重新指导会用新图；取消/关闭时迟到结果不会重开高亮。先验证这一条路径，再增加多屏选择和统一观察入口。
