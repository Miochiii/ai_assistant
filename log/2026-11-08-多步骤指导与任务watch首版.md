# 多步骤指导与任务 watch 首版

本轮目标：用户在软件中手动操作，助手依据当前画面验证当前步骤，再提示并高亮下一步。实现不调用点击、键盘或鼠标执行器。记忆部分仍等待跨日验收。

## 实现入口

在助手面板输入“教我……”时，现有 `PanelChatModel` 请求模型返回当前指引、首个视觉目标、最多 12 步计划以及每一步的可见完成条件。首个目标不可见、缺少有效计划或窗口绑定时，不启动自动任务 watch，保持澄清/旧单步路径。已有任务中重新输入“教我……”会结束旧任务并建立新任务；计划仍是模型建议，不是已经验证的操作轨迹或 PreAct 程序。

`ResidentHost` 保存任务、步骤和完成条件；`TaskWatch` 读取该任务，复用现有 mss 截图适配器及来自 see-now 的 `FrameChangeAnalyzer` 本地差异分析。没有另外启动一套付费视觉后端。

## 观察与推进

1. 初次截图隐藏助手面板和高亮，绑定当时的前台根所有者窗口 HWND 与 PID。后续不跟随到任意其他软件。
2. 每两秒尝试本地采样，只保留差异分析所需的前帧信息，不把整段截图历史传给模型。
3. 窗口位置/尺寸、前台所属弹窗或有效画面区域变化时隐藏旧高亮，进入等待稳定；连续两次采样稳定后才能请求验证。模型验证之间至少间隔八秒。
4. 验证请求包含当前画面、任务、当前步骤及完成条件、后续一步。模型只能输出 passed/failed/unknown，不能调用工具。
5. 收到结果后再截一张本地画面，比对窗口归属、几何和采样差异。推理期间画面变化、切换窗口或不可观察，均保留当前步骤，不采用旧坐标。
6. passed 只推进一格；有后续步骤时显示文字，并采用在本次图中重新定位的下一步目标。failed 可重新标出当前步骤；unknown 不猜坐标。失败后没有画面新变化就不持续重复调用模型。
7. 全部步骤通过后停止任务 watch。取消、暂停、换任务或关闭会使迟到验证结果失效；同一时刻最多一个步骤验证。

人工“检查当前步骤”入口保留，用来覆盖轻微变化未触发本地检测等情况。它与自动检查共用验证和失效检查，不直接跳过验证。

## 窗口与自身 UI

`tools/coach_overlay/watch_window.py` 用只读 Win32 查询完成前台/根所有者/PID 检查。绑定窗口失去前台、最小化、句柄对应进程变化时停止取图；归属同一根窗口的前台弹窗会加入截图范围。窗口移动、缩放重新计算范围。初版不支持跨进程的新软件接力，不承诺覆盖所有自定义弹窗或遮挡形式。

捕获前通过文件回执等待 Orb 隐藏；高亮进程也新增对应 generation 的隐藏回执，不再只等待固定时长就假定已隐藏。采样后仅在画面没变的情况下保留/续期原高亮，变化时清除。Orb 获得焦点并有新鲜心跳时，自动采样暂缓，避免用户输入过程中反复隐藏面板；手动检查仍可主动取图。

这仍是隐藏后截图的兼容路线，可能看到面板或提示短暂消失。未启用过去产生黑边/不可见问题的 WDA 强制排除，也没有安装 ffmpeg。

## 和陪伴 watch 的关系

不需要先运行 `/assistant-model-watch`。有有效任务计划后，任务 watch 自行工作。

若陪伴 watch 原本开启，任务存在且未完成时，暂停它的新模型唤醒并丢弃陪伴播报；结束或完成后恢复原有行为。初版保留陪伴 watch 的本地采样，不是统一成一个跨模式采集进程；已经发出的陪伴请求不能撤回，但不会在任务期间插播。

## 操作与验收

本轮修改了 Host JavaScript 与 Orb helper，需要完全退出并重启 Harness 后打开助手。

1. 打开一个无重要内容的记事本窗口，保持它在前台且完整可见。
2. 在助手面板输入：“教我在记事本里打开文件菜单，再打开另存为对话框，打开对话框后就结束，不保存文件。”
3. 应出现“已开始 N 步指导”，并显示当前步骤与高亮。若模型只提问或没有生成计划，不能把普通高亮当成 watch 已启动。
4. 输入 `指导状态` 可查看任务的 steps、conditions、target_window 和 watch.stage/calls，不请求模型。
5. 返回记事本，按提示手动打开文件菜单；等待两次稳定采样及模型响应，观察是否只推进到下一步并重新定位。
6. 打开另存为对话框后应验证完成，不能自动保存。未操作、失败、切走窗口或有歧义时不得直接跳到任务完成。
7. 输入 `暂停指导` 后不再自动采样；输入 `继续指导` 恢复。输入 `取消指导` 清除任务及高亮。右键菜单也有暂停、继续、检查和结束入口。

`watch.stage`：waiting_change 等待变化；waiting_stable 等待稳定；checking 正在验证；waiting_window 暂不可采集（包含前台不符或面板交互）；idle 未运行。模型错误、失败或 unknown 仍保持原步骤；必要时使用 `检查当前步骤`。

## 验证证据和局限

已通过离线模拟：不变画面零验证请求；变化后稳定再验证；连续动画不推进；failed 不推进或连续重试；两步逐步完成；取消后迟到结果无效；重复验证单飞；模型返回期间画面变化拒绝成功；窗口几何和前台变化检测；计划输入校验；计划到 Host 和下一步高亮接入；隐藏回执对应正确 generation。

已有指导/聊天/协议/高亮/watch 回归也通过。Python 语法检查和六项像素差异/模拟 Win32 窗口绑定测试通过。所有模型测试使用模拟 stream，未调用付费 API，未进行真实记事本多步骤验收。测试临时目录由测试 finally 清理，未改动记忆库。

本地差异使用 64×36 采样和小区域过滤，会漏掉很小的状态变化；持续动画可能迟迟不稳定。模型的 passed 是视觉判断，并非经过统计校准的成功证明。真实验收需重点检查菜单/弹窗、中文输入法、窗口缩放以及用户切回助手时的行为。当前阶段不要将这一结果直接升级为自动键鼠操作授权。

## 主要修改位置

- `task-watch.js`：本地变化/稳定门控。
- `resident-host.js`：多步计划、单飞验证、取消失效、步骤推进和人工命令。
- `panel-model.js`、`visual-target.js`：计划生成解析、首步截图复核、窗口坐标映射。
- `panel-guidance.js`：按完成条件验证、定位下一步/当前步骤。
- `panel-session.js`：窗口截图、样本清理、watch 调度、推理后的画面复核。
- `highlight-controller.js`、`coach_overlay.py`：高亮隐藏确认和恢复。
- `capture_once.py`、`watch_window.py`、`mss-adapter.js`：只读窗口绑定与截图元数据。
- `model-watch.js`、`index.js`、`orb-helper.cjs`：陪伴播报抑制、暂停继续菜单、交互焦点心跳。
