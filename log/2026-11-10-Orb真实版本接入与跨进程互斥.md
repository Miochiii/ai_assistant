# Orb 真实版本接入与跨进程互斥

承接切换事务开发。本轮完成 SQLite 版本接口、可信 Host 提供器、双路径跨进程互斥，并验证真实版本进入 Harness 原生门禁。正式 Orb/profile/记忆数据库未修改；没有付费请求或桌面动作。

## 已实现

- V2 增加 `memory_generation`：事务内绑定数据库路径、user/project、全局 enabled、作用域 consent revision 和当前有效记忆指纹。关闭时仍返回非空 token；不输出记忆正文。原 `rag_version` 的关闭返回 null 契约不变。
- MemoryHost 允许指定工作区在全局关闭时查询这一个控制接口，其他采集/召回仍受原开关约束；没有扩大工作区白名单。
- `generation.js` 校验返回值，`generation-host.js` 作为应用级独立入口提供 `orbMemoryGeneration.current()`，复用 MemoryHost 的可信作用域。该入口不采集消息、不注册模型工具、不自动注入或调度整理，尚未安装到正式 profile。
- `process-lock.js` 使用 Windows 本机命名管道分别占有 **切换状态文件** 和 **Orb 绑定文件** 的规范路径。不同 profile 共用状态库、不同状态库控制同一绑定均会冲突；部分获取失败释放已占有的锁。管道不接收业务命令，无 TCP 端口、PID 回收、超时抢锁或删除陈旧锁文件。
- Orb adapter 在获得双锁后才加载状态；获取失败时公开变更方法不能绕过锁，插件销毁时释放。崩溃后由 OS 回收。门禁仍在 Orb host 薄适配侧，不依赖 generation 提供器存活；提供器不可用时相关旧会话拒绝继续请求。
- `sync_orb_memory_dev.mjs` 校验开发副本 manifest 中已有文件哈希后，仅同步本项目扩展文件。发现人工修改即拒绝覆盖。开发副本已同步并增加 process-lock 文件；安装源未改。

## 验证结果

1. Python V2 20 项通过，包括关闭/开启、全局关闭、撤销和不同 scope 的版本变化。
2. Node 32 项通过（Host 13、来源 5、会话准备 6、切换事务 7、双路径互斥 1）。
3. `check_orb_generation.mjs` 使用真实 Python CLI、SQLite 临时数据库、MemoryHost 和提供器，验证稳定 token、开关失效、异工作区拒绝、配置损坏拒绝。报告 `results/memory/orb-generation-smoke.json`。
4. `check_orb_process_lock.mjs` 启动两个真实 Node 进程，竞争同一命名管道；第二个被拒绝。强制终止持锁测试进程后，新进程取得锁；大小写路径指向同一个锁。报告 `results/memory/orb-process-lock-smoke.json`。
5. `check_orb_cutover_native.mjs --sqlite-generation` 使用真实安装 SDK、真实 SQLite 版本提供器、磁盘状态和模拟 Orb runtime，5 次假模型请求通过。关闭/重新开启对应实际 consent 更新；旧调用者通知被阻止；新会话恢复保持干净；推理中版本变化后的合成工具调用未执行。报告 `results/memory/orb-cutover-sqlite-native-20261110.json`。

隔离测试数据已由各脚本清理，报告仅包含检查结论与计时。最初沙箱阻止子进程；一次自动审批因额度未完成，用户要求继续后重试获准。锁测试最初发现测试脚本换行转义错误，修复后通过，不能把初次整组退出码当作全部通过。

## 性能发现与当前限制

真实版本链路 25 次检查累计 **4351 ms**，最大单次 **184 ms**，约 174 ms/次。当前每个流片段都调用 CLI，频繁启动 Python 会显著拖慢回复。这是少量本地样本，不是 P95 或真实模型端延迟。

正确性链路已接通，但此模式暂不用于真实聊天。下一步应增加助手独立的常驻轻量版本查询 worker，串行处理控制请求，每次仍从 SQLite/配置取最新状态；取消/异常/配置变化时明确失效。不能通过长时间缓存 token 或取消在途检查换取速度。

当前 generation 读链会沿用 MemoryGateway 初始化表的行为，并非操作系统层只读连接；本轮只操作测试数据库。全局配置 off→on 若发生于两次观测之间且恢复完全相同值，现有 token 不保存未观察到的文件变化历史；作用域 consent off→on 有修订号，可以检测。

后台通知投递确认仍缺公开接口，开发版继续暂缓有后台登记的 caller；Lasso/翻译仍使用保守限制。尚未在隔离 profile 中加载完整 Orb UI，也未验收真实 Harness 会话文件后端。跨进程锁是同一 OS 上遵循协议的实例互斥，不是防止外部手工改文件或断电持久性的保证。

下一步顺序：常驻版本查询与延迟复核 → 后台通知完成确认 → 隔离 profile/测试库的真实 UI 切换和恢复 → 正式安装准备。无需用户现在重启。
