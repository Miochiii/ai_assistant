# 03：陪伴控制与状态面板——DS 开发交接

日期：2026-11-12。待实现方案；用户已确认视频陪看实测正常。先阅读同目录《02-ASR接入技术手册》的基线信息。

## 1. 目标与明确边界

在 Orb 现有设置/控制入口增加真实可用的开始、暂停/继续、停止和状态反馈。两个模块始终独立，用户手动选择；不要加入自动判断场景、自动切换引擎、双引擎同时运行或重写上游视频循环。

重点解决已发生的问题：用户下拉框选择“视频陪看”但没保存，实际仍为 screen，看见文字回复误以为视频桥已经连通。今后界面必须分别显示“编辑中的选择”“已保存的选择”“实际运行模块”，不能只用下拉框值标识正在运行的模块。

## 3. 推荐结构：薄控制层 + 原模块适配

新增独立的小控制/状态适配文件，避免把逻辑继续散入 4 万行 host bundle。host 仅挂路由、绑定会话和生命周期；client 仅展示状态与发动作。

先定义稳定接口（以下是建议新契约，不是现成 API）：

```text
GET  /.dsh-orb/companion-status
POST /.dsh-orb/companion-control
     { action: start|pause|resume|stop, requestId, expectedRevision }
```

沿用当前请求身份、Origin/Host 校验及响应约定；状态 GET 必须纯读，不建段、不启动桥、不读用户 cookies、不调用 LLM/ASR。增加路由时不要放在 rejectionStatus 校验之前。

屏幕适配器复用 OrbCompanion 的 start/stop/describe 和已有队列。视频适配器复用插件原生命周期。先核对 package exports：不要假设内部文件都可以用裸包名导入。需要新增稳定导出时用最小补丁并记录，避免复制整套 watch-loop。

特别注意：视频状态在进程内，必须连接 DSH 中已加载的同一模块实例。另起 Node 子进程 import 后查询 loopStatus 看到的是另一个空循环，不能当作真实状态。同样不要在外部独立启动 chat 服务来把“未连接”伪装成正常陪看。

启动若必须让原生代理驱动，可复用已有 preempt/sessionController 入口，但 UI 只能先显示“请求已提交/启动中”。真实桥/循环反馈后才能显示“陪看中”。不能点击按钮后立即乐观设置 running。

暂停/停止优先通过原模块直接控制，避免为了停循环额外发一轮模型请求。需要同时取消所属原生代理等待/预取/排队语音，阻止代理下一拍又启动；不要误停别的普通任务或全部会话。若无法直接挂接则先说明限制，不能只取消聊天任务就宣称视频循环和语音队列已停。

## 4. 状态契约及状态机

建议状态结构：

```json
{
  "revision": 1,
  "selectedMode": "video",
  "runningMode": null,
  "sessionId": null,
  "phase": "stopped",
  "bridge": {"service": "unknown", "extension": "unknown", "fresh": false},
  "media": {"title": null, "positionSeconds": null, "confidence": "unknown"},
  "transcript": {"source": "none", "phase": "idle"},
  "lastError": null,
  "updatedAt": null
}
```

这是初始/未知示例，不要把 null 自动转成 0。实际字段应从模块状态取值；输出不包含凭证。phase 至少覆盖 stopped、starting、running、paused、stopping、error；ASR loading 是子状态，不一定让整个陪看变成 error。

- start：确认已保存模式、会话归属、模块可用和无冲突任务 → starting → 模块证据确认 running 或明确错误。
- pause：屏幕停止采样并保留其已有可恢复上下文；视频使用上游停止/挂起语义并标明“继续时重新跟随播放位置”。不承诺不存在的精准续队列。
- stop：阻止新工作，取消所属请求和待发言，清理句柄；迟到回调不更新当前状态。清理完成后 stopped。
- 模式切换：默认先停止再保存。禁止 running/starting/stopping 中静默切换。暂停的旧模块也需释放后再切。
- 错误恢复：保留短错误原因及可执行下一步，不把配置“未安装”和网络“暂不可达”混成一个错误。
- 退出 Orb/新会话/切会话/插件卸载：释放本控制层所属资源，状态不可沿用旧会话。

用串行控制队列与 revision/runId 防止重复点击和迟到结果。注意不要在队列内部 await 一个再次进入相同队列的方法（例如 preempt 间接 stopTurn），会死锁。检查现有 installOrbCompanion 对 stopTurn/newSession/openSession 的包装后再接按钮。

## 5. 面板具体显示和交互

1. 顶部明确显示“已保存：屏幕陪伴/视频陪看”；下拉框变更后出现“尚未保存”。保存失败保持已保存标记不变，不能让失败选择看起来已经生效。
2. 控制按钮只作用于已保存模式；有未保存修改时禁用启动并提示保存。保存后不自动启动。
3. 运行状态独立显示模块名、阶段、最近错误；按钮 loading 防连点，停止应可中断 starting。
4. 屏幕模式保留原采样/模型/发言间隔及计数。视频模式显示原插件设置入口，不套用屏幕间隔。
5. 视频桥拆成三层：本机服务是否可达、是否收到扩展报告、当前视频位置是否新鲜。目录存在不等于扩展已加载，9377 端口开放不等于当前视频已连上。
6. 位置过期显示“等待播放信息”，不继续把旧秒数显示为实时。旧 hello 文件只能证明曾报告过，不能保证现在仍在线。
7. 对白来源显示“站点字幕/字幕文件/语音识别/暂无”，并展示 ASR 加载/失败。画面上 OCR 看到的字幕不等于已取得音轨或字幕轨。
8. 设置保存反馈靠近下拉框/按钮，不只放在卡片最底端；支持键盘焦点、label 与 aria-live 状态提示。

先保留“需要保存”的明确语义，不把所有输入改成自动启动。若以后选择自动保存模式，也要等待服务端成功并在失败时回滚显示，这不是本次必需项。

## 6. 桥端口、状态刷新与成本

原扩展当前指向 127.0.0.1:9377；原插件 watch.json 支持 chatPort，但修改服务端端口不意味着扩展跟着变。不要为排错随意换端口。冲突时明确报告占用并核对所属服务。

面板可见时每 2–3 秒读一次轻量状态，隐藏后暂停或降频；请求不重叠，组件卸载取消。也可复用现有事件推送，但不为此引入新消息总线。

GET 状态调用次数可以很多，付费模型/ASR 调用次数必须为零；不要通过定时向代理发送“陪伴状态”实现面板刷新。loopStatus / position 的语义不同：有进度不代表循环 running，要组合真实来源。

视频设置页已有 token 机制，复用同源原入口。不要把含 token 的地址写到日志/分享文档，不把新控制接口做成无认证的 localhost 通用执行器。

## 7. 验收矩阵与已有测试

| 场景 | 必须满足 |
|---|---|
| 只切下拉框不保存 | 提示未保存，已保存模块不变，不能误启动新模式 |
| 保存失败/插件未加载 | 清晰错误，不回退启动另一个模块 |
| 屏幕开始/暂停/继续/停止 | 实际采样与模型请求跟随状态变化 |
| 视频开始 | 先 starting；真实工具/循环启动后才 running |
| 桥断开/无视频/视频暂停 | 分别显示，不把正常暂停写成未连接 |
| 视频拖动/换片 | 原版同步行为保持；旧识别和评论不污染新片 |
| 连点、启动中停止、切会话 | 无双循环、无死锁、无旧回调回写 |
| 状态刷新 100 次 | LLM/ASR 额外调用为零，无建段副作用 |
| 原插件窗与 Orb 同时存在 | 控制的是同一个视频循环，不重复安装或启动 |
| 重启 | 保留已保存选择，不自动恢复采样/监听 |

已有 `tests/test_orb_companion.mjs` 含真实 host 方法提取执行测试，覆盖屏幕/视频手动路由、插件缺失、切换阻止等。加状态机、幂等、停止取消、未保存 UI 行为测试；保留原来的测试。相关命令：

```powershell

node --check dsh_orb_full_orig/dist/host/index.js
node --test --test-isolation=none tests/test_orb_companion.mjs tests/test_companion_stream.mjs
```

完成后真实重启 DSH，点一遍两种模式与故障状态。记录哪些是 mock 测试、哪些是真实 UI/视频验收，不能相互替代。

## 8. 修改范围与交付

优先：新增薄适配文件 → 加状态 GET → 加控制 POST → 前端显示与按钮 → 异常和竞态 → 实测。ASR 未完成时先显示未配置，不阻塞其余面板开发。

不要改变已验收 Memory Evolve、工作区/会话数据、上游插件更新策略；不要将两模块融合。外部插件代码变更必须有可重放补丁和回退记录。

改开发包后更新 package.json、加载版本日志、MIO-README.md 和 MIO-DEVELOPMENT.json 对应文件哈希。提交/交付包含修改清单、测试命令与结果、用户如何重启验收、仍未支持的行为。原安装备份在 runtime/watch-together-install/20261111-222641；之后配置有变动不能整包覆盖旧备份回退。
