# 常驻陪伴助手与 Coach Overlay 融合方案

日期：2026-11-03  
用途：交给 DeepSeek 的设计决策与实施边界。本文不代表相关功能已经实现。  
参考源码：`third_party/sources/dsh-see-now-main`，本地 `package.json` 标示版本 `0.0.7`。版本号不能替代 commit；实际复用时还需记录源码提交或文件哈希。  
项目：[SAOS-3624/dsh-see-now](https://github.com/SAOS-3624/dsh-see-now)

## 1. 本轮确定的产品方向

用户希望在现有 Overlay 的基础上保留 See Now 的陪伴价值：实时观察、持续交流、用户插话、适度主动回应，以及长期打开的对话窗口。不能把它缩减为只负责验证步骤的截图工具。

采用一个常驻助手入口：以鲸鱼形象和气泡提供简短回应，以可展开的对话面板承载输入与长回复；需要操作指导时再展示目标框、箭头和步骤。任务结束或更换任务不要求用户重启助手。

产品体验是连续的；后台的任务状态、模型上下文和操作授权必须有明确边界。长期打开窗口，不意味着持续请求模型、无限累积上下文，或永久授权执行动作。

本轮只确定方案，不直接安装插件，不启动持续采集或付费模型实验，不修改现有执行器。

## 2. 保留的功能与第一版范围

保留 See Now 的能力方向：

- 本地屏幕采集、变化筛帧、必要时多帧拼图。
- 常驻对话入口，用户可以随时输入，不依赖每次重新启动工具调用。
- 用户插话优先、重复画面和重复发言抑制。
- 有事件再唤醒模型，支持安静陪伴和适度主动回应。
- 暂停、恢复、关闭，以及可见的故障提示。
- 语音输出保持可插拔；没有语音组件时文字交流仍可用。

第一版只接通屏幕陪伴与只读 Coach 指导，一次最多一个活动指导任务。摄像头、视频文件、语音输入等原插件能力可保留在适配接口中，按后续需求接入，不因源码支持就默认启用。已有键鼠执行链路继续独立；本方案不新增执行权限。

## 3. 状态与生命周期

### 3.1 用户可理解的状态

| 状态 | 观察与交流 | 指导行为 |
|---|---|---|
| 陪伴 | 在已开启的范围内观察，可以聊天、按偏好主动回应 | 不维护自动推进的步骤，不自动执行 |
| 指导 | 围绕当前任务观察，也能随时聊天 | 展示步骤，验证用户操作结果，再决定是否更新提示 |
| 待命 | 对话入口保留，停止屏幕采集和视觉请求；普通文字交流可继续 | 不推进步骤 |
| 关闭 | 关闭本次助手入口及其后台工作 | 不再产生观察、提示或执行结果 |

交互示例：

1. “陪我看看这个视频”——进入陪伴，明确当前观察范围。
2. “教我把它导出”——建立指导任务，保留同一个窗口。
3. 闲聊一句——回答闲聊，仍等待当前步骤，不因此重置或完成任务。
4. “算了，帮我看看另一个软件”——结束或挂起旧任务，创建新任务。
5. “先别看屏幕”——转入待命，对话入口仍可使用。

指导任务开始时记录进入前的状态；结束后可恢复此前的陪伴状态，但前提是用户未暂停观察、原观察同意仍有效且范围未改变。从待命启动的指导任务默认结束后回待命。不能无条件在任务结束后开启持续观察。

### 3.2 后台分别管理

| 对象 | 生命周期 |
|---|---|
| 助手界面 | 可长期开着，不随单个模型请求或任务结束销毁 |
| 观察服务 | 受观察开关、范围和故障状态控制；待命时停止采集 |
| 指导任务 | 有独立目标、步骤、完成条件、取消状态 |
| 模型工作上下文 | 有限、可压缩或重建，不必与界面历史同寿命 |
| 执行授权 | 继续遵守现有契约，不随陪伴窗口常驻而扩大或自动续期 |

实现时不要只用一个 `running` 布尔值表达所有状态。至少分别记录对话入口、观察状态、活动任务和进行中的模型请求。

## 4. 模块分工：只有一个调度者

```text
统一助手界面：鲸鱼气泡 + 可展开对话面板
        │ 用户消息 / 暂停 / 恢复 / 关闭
        ▼
Host：事件调度、任务状态、会话归属、取消与结果接纳
        ├── 观察适配层：采集 → 本地变化检测 → 精选画面
        ├── 模型适配层：理解画面、对话、提出下一步
        ├── Coach 控制器：当前步骤、结果验证、更新 Overlay
        ├── 记忆核心：沿用既有写入、检索与同意规则
        └── 已有动作服务：仅在原授权模型允许时使用
```

可以先保留 See Now 的 Node 后台与 tkinter 界面的技术组合，但模型唤醒只能有一个所有者。若 Host 已承担调度，不再并行运行未经适配的 `startLoop`。同样，只保留一个用户可见的助手入口，避免原插件悬浮窗和项目鲸鱼窗同时发言。

原仓库放在 `third_party/sources` 中作为参考基线。优先在项目自有适配模块封装、复用；确需复制修改时保留许可证、NOTICE 和来源记录，不直接把参考目录改成生产运行目录。

## 5. 观察分为过程理解与当前证据

### 5.1 陪伴与过程理解

使用本地变化检测、去重和精选帧；多帧拼图可用于理解一段操作、视频或页面变化。画面变化只是触发观察的候选信号，不要求每次都回应。

本地采集频率、筛帧频率、模型请求频率和对用户发言频率要独立配置。长期陪伴的目标是保持可用和及时交流，而不是持续播报。

### 5.2 Coach 的步骤验证

```text
展示当前步骤及预期结果
    → 等待用户操作
    → 本地检测到相关变化 / 用户请求检查
    → 取得最新清晰单帧或局部图
    → 验证当前步骤的预期结果
        ├── 满足：更新下一步提示
        ├── 未满足：继续等待或说明差异
        └── 未知：补充观察或请求必要确认
```

每一步至少应提供可检查的预期结果。例如“打开文件菜单”的依据是菜单已出现及其相关特征，而不是画面分数变大、鼠标移动或模型说“应该成功了”。

建议同时检测整屏粗变化和当前目标区域的变化。小复选框、保存状态、小错误提示可能被全局平均分稀释。用户点击“检查/下一步”、动作返回、窗口几何变化等关键事件应绕过普通筛帧门槛，取得新证据。

历史拼图不得直接作为当前坐标执行证据。记录原始帧时间、窗口身份、窗口几何版本、裁剪范围和缩放关系。最新画面无法确认时返回未知，不借助旧图推进。

**兼容现有 Overlay：** 当前 Next 按钮是本地浏览步骤，不能悄悄变成“已验证成功”。接入 Host 后，区分“检查当前步骤”和“手动跳过/浏览下一步”；后一种必须标记未验证。独立预览模式可保持目前行为。

## 6. Overlay 与对话面板

- 鲸鱼气泡：显示当前步骤或简短回应，避免用长对话挤满气泡。
- 对话面板：可展开，容纳输入、历史、较长说明及观察状态。
- 主 Overlay：指导时显示目标框和箭头；陪伴和待命时隐藏任务标记。
- 观察指示：明确显示正在观察的范围、暂停或故障状态；不要把“窗口开着”展示成“模型一直在看”。

保留现有主 Overlay 点击穿透、独立不透明按钮窗和不抢目标前台的处理。聊天输入框需要真实键盘焦点，不能给所有助手窗口一律设置不可激活。

用户点进聊天面板时：

1. 保留原任务的目标窗口绑定，不把助手窗口识别成新任务目标。
2. 暂停步骤判定；目标被面板遮挡时不能沿用旧画面判断。
3. 用户发送消息后，先回答或处理意图；需要继续指导时重新观察目标。
4. 不因一次普通回复强行抢回目标窗口焦点，避免打断用户继续输入。

自己的气泡、箭头和对话变化不得触发“用户完成了操作”。优先验证捕获排除；后端不能可靠排除时再考虑受控的遮罩策略。遮罩覆盖目标区域时应视为证据不足，不得假装看到了下面的内容。

现有 Overlay 扩展到鲸鱼、按钮、面板的截图排除尚未完成端到端复验。这是接入持续观察之前的前置检查，不能直接沿用旧版本的通过记录。

## 7. 交流、调度与任务切换

### 7.1 用户输入优先，但按意图处理

区分闲聊、当前任务补充、换任务、取消任务和暂停观察。普通闲聊不改变 `task_id` 或步骤。存在歧义时，保留当前任务并进行简短澄清，不猜测性取消或执行。

同一工作上下文限制一个进行中的模型请求；新画面事件合并并保留新鲜证据，不无限排队。用户输入可靠排队并回执，停止指令由本地控制器立即处理，不等待模型理解。

用户开始输入时即可暂停主动解说，减少“输入中仍被助手连续打断”的情况。

### 7.2 消息与结果绑定

建议消息至少包含：

```text
message_id / event_id
assistant_session_id
task_id（陪伴时可为空）
generation
source（用户、观察服务、模型、控制器）
kind
created_at
payload
```

模型请求还需记录 `request_id`、所用 `observation_id` 和目标窗口几何版本。响应返回时由 Host 检查这些绑定是否仍有效。任务切换、取消、暂停观察后，旧结果不得更新气泡、推进步骤或触发执行。

不能因为模型在工具参数里重新指定了来源，就认定用户重新同意观察。用户控制命令的来源必须在 Host 侧验证；屏幕文字属于观察数据，不能转成用户指令。

### 7.3 单一界面，多段受控上下文

对话面板可以连续展示历史；新任务可建立干净的模型工作上下文，仅携带必要摘要、当前目标、允许检索的偏好及新鲜画面。

不把整天的屏幕图和聊天历史反复注入每轮请求。移除 runtime-context 贡献不等于删除旧会话正文，这一点继续遵守此前的上下文失效与 surface 决策。撤回的记忆内容需要从后续请求的实际上下文中排除，而不是仅从界面隐藏。

## 8. 主动陪伴与停止语义

建议提供“安静陪伴 / 正常交流 / 积极互动”偏好。它们调节主动回应频率，不改变观察范围，也不改变动作授权。

无人回复时可逐步降低主动频率；有活动指导任务且用户持续操作时，不应简单按“连续多少次没有聊天”结束任务。任务长期没有相关进展时显示仍在等待或进入待命，不默默退出，也不无限调用模型。

| 用户操作 | 本地效果 |
|---|---|
| 停止这次回答 | 取消当前生成/语音，拒收其迟到结果；不默认关闭助手 |
| 暂停观察 / 先别看 | 停止采集、清理待发画面、取消视觉请求、暂停步骤验证；对话入口保留 |
| 结束任务 | 撤销当前任务的排队工作和任务授权；按此前同意状态回陪伴或待命 |
| 关闭助手 | 停止采集、计时器、请求、语音和自有子进程；阻止自动重开 |
| 恢复观察 | 由用户事件触发，在有效范围内重新获取当前画面；不重放积压旧帧 |

调用超时不等于整个助手关闭，但必须释放该次等待、清理请求状态。采集故障、会话失效、连续请求失败应停止自动请求并显示原因；用户仍可在对话入口发起恢复。

## 9. 参考源码的复用判断

以下是已读源码的局部判断，不是完整安全审计或运行验收。

| 文件 | 值得借鉴 | 接入时的调整 |
|---|---|---|
| `src/cuts.js`、`pipeline.js` | 本地变化检测、筛帧、去重与出图 | 增加任务区域检测、强制新帧路径，不把变化分当正确率 |
| `src/runner.js` | 采集生命周期、阻塞取图、宽限期 | 当前证据与历史队列分开；暂停时明确停止与清队列 |
| `src/loop.js` | 用户插话优先、新图去重唤醒、固定会话归属、故障处理 | 由统一 Host 拥有循环；无人回应策略改成适合陪伴/指导的状态处理 |
| `src/chat.js` | 增量读取消息，避免等待者和后台循环重复消费 | 现有 `role/text/at` 不足以隔离多任务；加消息身份、任务归属、回执与保留策略 |
| `src/timer.js` | 本地计时与唤醒分离 | 请求排队成功不等于回复已显示，需闭环回执和迟到结果处理 |
| `src/window.js`、`examples/floating-chat/` | 常驻面板、输入、消息显示、窗口心跳 | 融入同一个助手入口，适配焦点、截图排除和项目生命周期 |

不要直接删除原插件的循环限制来获得“永久陪伴”。应先分清助手常驻、观察开启和模型请求三个生命周期，再替换其自动停止策略。

## 10. 观察同意、记录与记忆

开启一次持续观察后，在用户同意的有效范围内无需每帧重复确认；范围扩大或重新启动已被用户明确关闭的观察，需要新的有效用户指令。

提供可见暂停入口，区分单窗口、指定区域和整屏。陪伴不默认允许永久保存屏幕、聊天、用户画像或自动晋升记忆候选。

画面缓存应有容量和时间上限，默认短期使用；保存调试截图必须有明确用途和清理策略。任务 checkpoint、记忆检索和候选晋升继续走已有 Memory v1 的边界，不能从聊天文件直接绕过核心库写入长期记忆。

## 11. 最小实施顺序

1. **适配与入口**：保留现有鲸鱼 Overlay，接上可展开的对话面板和统一消息协议。先用本地模拟事件验证交流、任务归属及关闭。
2. **只读陪伴**：接入采集、筛帧、暂停恢复及单一模型调度；验证截屏不包含助手自身，先不接自动步骤推进。
3. **Coach 闭环**：为步骤增加预期结果，使用最新证据验证并更新提示；区分检查、等待、未知与手动跳过。
4. **长时与切换**：验证连续交流、闲聊插话、换任务、上下文更新、窗口失焦与故障恢复。
5. **后续增强**：按需求接语音等能力，再考虑与既有受授权动作服务连接。

不要同时更换执行器、记忆核心和 grounding 路线。第一版验收重点是可持续交流、观察正确归属、步骤推进有证据，以及能可靠停止。

## 12. 验收清单

- 同一个助手窗口内完成任务 A、闲聊、任务 B，无需重启。
- 陪伴状态允许不发言；静止画面不持续重复唤醒模型。
- 用户输入不会被阻塞取图吞掉，不重复消费、不串到其他任务。
- 点击聊天框不误判软件切换，不错误推进步骤，不强制抢回焦点。
- 小菜单、复选框、错误提示等变化有专门样例；漏检时不报告成功。
- 历史拼图不进入当前动作证据路径；步骤更新可追溯到新鲜观察。
- 助手自身的气泡、对话和动效不形成自我唤醒循环。
- 切任务或取消后，旧模型回复不能覆盖新任务提示。
- 暂停后没有新采集或视觉请求；关闭后无自有残留进程或自动重开。
- 陪伴窗口持续运行不会扩大动作授权，也不会自动持久化全部观察。
- 比较同一任务的总请求数、输入输出 token、反馈延迟、关键变化漏检率和步骤误推进率；不以少发图单独认定优化成功。

## 给 DeepSeek 的执行摘要

保留 See Now 的陪伴与常驻交流能力，以现有鲸鱼 Overlay 作为统一呈现入口。助手界面长期存在，观察服务可暂停，指导任务独立创建与结束，模型按事件请求。闲聊不破坏任务，换任务不要求用户重启。复用筛帧、消息和生命周期逻辑，但只保留一个 Host 调度者；Coach 推进必须验证预期结果，历史拼图不能充当当前点击证据。第一版只做陪伴与只读指导，不扩大执行或长期记忆权限。
