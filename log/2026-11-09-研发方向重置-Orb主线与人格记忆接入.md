# 研发方向重置：Orb 主线与人格记忆接入

日期：2026-11-09。用途：Codex / DeepSeek 新会话共同交接入口。

**本文记录用户最新决定，优先于旧日志中的下一步安排；代码现状和计划必须分开读。用户后续指令优先。**

## 1. 最新目标与优先级

做一个以 Orb 视觉操作为主线、拥有统一人格与跨会话记忆、可开启自主看屏陪伴的常驻桌面助手。

用户明确调整为：

1. 以完整 Orb 的截图、窗口选择、键鼠操作、操作后反馈循环为基础。
2. **当前研发重点：人格与记忆接入，先完成记忆服务与 Orb 的连接。**
3. 随后增加可开启/停止的自主观察陪伴模式。
4. 指导模式的具体交互形式暂定，用户还有新想法。暂停旧高亮/自动多步指导的扩展，不自行恢复旧任务。
5. PreAct 作为后续经过验证的用户流程积累层，暂不扩大开发。

不以“软件逐个特化”为通用层主要路线。不要继续从 Orb 拆几个组件后重新造完整桌面循环；也不要把旧指导状态机、watch 和所有限制整体搬入 Orb。

## 2. 作出调整的证据

用户已安装原版 Orb 并实际测试：能够点击、输入，点偏后能重新观察并纠正；QQ 视频通话占用前台时也能切换到正确软件。用户反馈整体速度可接受，但点击准确率不高。

这是用户的真实定性反馈，不是已测得的成功率。纠错能力有价值，但不能宣称模型定位可靠或无限重试安全。指导观察用户行为与 Agent 自己执行动作也不能直接等同。

旧项目多步指导经历窗口绑定、几何失效、窗口接续等修复，离线回归通过，但用户真实反馈仍有圈定按钮和步骤检查错误。**真实指导尚未验收，测试数量不能代表端到端能力。**这些补丁留在旧代码中供参考，当前停止沿这条链路继续补洞。

## 4. 记忆做到哪里

### 已实现且用户已验收的基础能力

- 原助手面板用户输入进入来源账本，跨日整理、提取有限的明确偏好，核验后入 SQLite。
- 用户已确认一次次日自动入库、显式查询，以及同工作区新会话自然语言召回正常（常用编辑器 PyCharm 示例）。
- 核心具有来源绑定、候选/有效状态、作用域隔离、版本、撤销、查询等机制。
- 当前自动采纳仅限部分沟通风格、语言和常用编辑器规则；冲突及其他偏好通常留候选。不是自动记住全部内容。

### 已实现，主要为离线验证

- 2026-11-09 增加 Host 管理的常驻 CPU 检索 worker，串行 stdio 协议、取消/超时、空闲 5 分钟退出；配置变化后重启。
- 每次先取 SQLite 有效快照，再由 worker 返回 ID，最后回到 SQLite 复核正文与版本。候选结果不直接成为权威记忆。
- 15 条合成记忆：冷查询约 16.07 秒、热查询约 0.75 秒；单条真实 Host 测试热查询含 SQLite 校验约 0.41 秒。不是 DS 对话总耗时承诺。
- 分段计时记录在 `runtime/memory/latency/latest-panel.json`，实际回复后生成，仅保留最后一份元数据。
- 用户把新记忆入库后的进一步验收推迟到次日，**不要记为已经完成后续真实验收**。

### 当前接入限制，必须先解决

- 这些能力接在旧助手面板，**尚未接入原版 Orb**。
- `memory-v2.json.allowed_workspace` 当前为项目根目录；Host 采用精确工作区匹配。Orb 工作区和可能生成的子会话目录不同，不能只打开记忆开关就认为能复用。
- 需要设计稳定的助手身份、Orb 所属会话和项目作用域映射；不能给每个临时子目录创建一套互不相通的个人记忆，也不能把其他工作区全部合并到同一库。
- 原自动整理调度属于旧面板生命周期：面板开启且空闲时检查已结束日期，周期约一小时，不是系统级全天后台服务。停用旧插件后，不能期待旧调度继续运行。Orb 接入必须明确新调度所有者，并防止两个 worker 重复整理。
- 目前只采集符合条件的真实用户面板消息；模型回复、工具结果、截图和主会话历史没有自动全部入库。迁移必须明确新的来源范围，后台代理结论不能冒充用户陈述。
- 旧 Harness 会话历史可能保留曾注入的记忆；清除 runtime-context 不等于删除历史。原面板依赖隔离请求、短历史失效及版本复核，**这些保证不能直接宣称适用于 Orb 持久会话**。
- 旧索引代次物理清理、完整副本删除、丰富事实/事件自动记忆、冲突更新界面、长期质量评测仍未完成。
- 变点检测目前是未校准的影子诊断，不自动删库或重建。
- 人格系统尚未完成新的 Orb 接入；旧固定提示语不等于完整角色卡系统。

## 5. 推荐集成方式：原版 Orb + 独立扩展 + 小型适配层

这是已讨论的优先方案，**尚未实施新插件**。

```text
原版 Orb / Harness 会话与工具生命周期
          ↕ 小型适配层
我们的人格、记忆、后续陪伴扩展
          ↕
独立记忆核心与 RAG（数据在 E 盘）
```

优先核实 Harness 的会话事件、工具注册、上下文生命周期接口，再决定最小接入。不能假设源码里出现的方法就是稳定公开 API。

不直接长期改 `C:\Users\Mio\.dsh\profiles\desktop\node_modules\dsh-orb`；更新会覆盖。只有确实没有扩展入口时才考虑小型可追踪补丁或开发副本，不默认 fork 整个 Orb，也不把所有旧助手代码复制过去。

人格是用户配置和表达偏好，记忆是带来源与状态的数据；二者不改写操作授权。前台面向用户的表达一致，不要求后台任务代理重复输出角色口吻。

Orb 设置里的后台 Agent 是按需调用的 `code_agent`：前台模型委派较长文件/代码任务时自动创建或继续标准会话，完成后通知前台。不是常驻看屏陪伴，也不是已经实现的每日记忆整理器。记忆整理不应依赖前台模型偶然决定委派。

## 6. 下采样与更新的已核实结论

### 图像

- 原项目陪伴观察会使用 See Now 风格 320×180 缩略图，变化检测使用 64×36 抽样。
- “教我”首次定位读取 `image_ref` 原图，不直接使用该缩略图。不能把已观察到的定位失败全部归因于 See Now。
- 步骤验证存在原图缺失时回退缩略图的隐患：缩略图可能裁剪，但坐标仍按原范围解释。迁移时精确定位不得走此回退。
- Orb 与旧项目都调用 Harness `attachments.saveImage`；模型最终输入尺寸需要实测。原图上传不等于模型输入细节未损失。
- 后续陪伴粗观察与精确操作分开：粗观察只负责发现值得关注的变化；操作与核对取新鲜、清晰、带坐标元数据的窗口图。

### 更新

安装版本内自动检查与安装分开；检查只通知，设置页/球菜单触发安装，Windows 可能在退出 Harness 后完成已触发的安装。不要把“自动检查”写成“默认静默自动升级”。UI 写每日检查，但该版本检查函数实际有一小时节流条件，不依赖 UI 文案推断实际频率。

日常使用最近验收通过的固定组合，保留升级通知；新版在隔离配置/测试库验证后切换。记录 Orb、Harness、适配扩展和数据库结构版本。回退需同时考虑配置和数据迁移，不只是降级 npm 包。兼容失败应明确停用受影响的记忆扩展，尽量保留原 Orb 基础功能；此降级策略仍需实现和测试。

## 7. C / E 盘存储边界

Orb 的 E 盘 Agent 工作区只改变任务工作目录，不自动迁移 Harness 全部数据。当前 C 盘 `.dsh/sessions`、`.dsh/attachments` 及缓存/运行时仍可能增长，安装包本身主要随更新变化。用户设置截图显示旧会话永久保留。

本次没有迁移或清理 C 盘。后续人格配置、记忆数据库、索引、整理中间数据明确放 E 盘。若要迁移 Harness 数据，应另行核实路径与迁移方案，不以移动 Orb 源码目录代替。

## 8. 新会话第一阶段任务

1. 只读核对已安装 Orb 与 Harness 版本、启用插件、会话事件与记忆可用接入口；不要先启动旧助手。
2. 追踪一条 Orb 用户消息的真实来源、会话 ID、工作区归属，以及前台与 code_agent 子会话的关系，确定采集去重键。
3. 明确用户记忆与项目记忆的作用域映射、老记忆复用范围，以及“不要记忆/关闭/纠正/撤销”的效果。禁止默认批量导入全部旧 Harness 历史。
4. 选择可避免旧正文长期残留的检索注入方式；如果宿主不支持干净请求/上下文替换，明确限制和方案，不用假设填空。
5. 形成最小适配方案后实现一个独立接入闭环：Orb 中一条用户明确偏好 → 来源入账 → 每日整理 → 有效记忆 → 新 Orb 会话召回。保留现有显式记忆命令或等价可理解入口。
6. 同时验证：重复消息不重复写、后台生成内容不冒充用户偏好、其他工作区不串库、关闭后不采集、撤销后不继续注入、扩展停用后 Orb 可用、重启后不会重复运行整理任务。

人格接入先做小型可版本化配置接口，与记忆分离；不同时大改外观、指导、自动动作协议和 RAG 后端。单纯聊天成功、单测通过或数据库出现一行不等于跨会话记忆验收。

## 9. 开发约束与交接纪律

- 不改已收尾的原 RAG 环境；优先复用助手目录现有适配副本；不安装 CUDA。
- 不擅自迁移/删除真实记忆、会话、附件、插件配置；临时数据仅清理本轮自己创建且已核对的路径。
- 遵循既有授权推进日常开发和小规模验证，不重复索要已经获得的许可；新付费服务、大额/批量实验或新的外部动作范围单独说明，不把历史单轮预算当永久额度。
- 用户需要配合重启或软件操作时再说明。当前文档编写不授权自动关闭正在进行的任务。
- 如 Codex 与 DeepSeek 同时工作，先约定文件职责，避免同时修改接入层和数据库契约。
- 不再把旧指导修复当本轮目标。每次报告区分：代码实现、离线测试、真实模型试验、用户验收。
