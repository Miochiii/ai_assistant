## 3. 推荐实现：接已有兼容服务，复用原转写链路

第一步盘点本机已经可用的 ASR 服务与配置，仅输出是否配置、模型名和脱敏地址，不输出密钥。Orb 自身有语音能力不等于其识别服务可用于视频：需要确认可接受音频文件、返回时间戳，以及 watch 的两条识别路径是否真正传入 hostAsr。不要凭服务名称就宣称复用完成。

优先接现成、稳定的本机兼容服务；没有现成服务时，比较机器资源后选一个成熟服务部署。若需要云端，由用户提供/选择供应商与凭证，不自行默认上传真实用户视频测试。不要为了 ASR 写第二套大模型代理，也不要把普通聊天模型当音频识别服务。

配置入口为 `C:/Users/Mio/.dsh/asr.json`；设置 DSH_HOME 时只读对应目录。配置文件优先于临时终端环境变量之外的默认值，但显式环境变量优先于文件。DSH 桌面启动不一定继承终端新环境，生产接入优先文件。

示例仅说明字段，不代表服务已经安装，model 必须换成所选服务的真实模型标识：

```json
{
  "baseUrl": "http://127.0.0.1:8000/v1",
  "model": "REPLACE_WITH_ACTUAL_MODEL",
  "language": "zh"
}
```

云端可使用 `key`。本地 loopback 服务上游允许不填 key；若服务自身要求认证仍须提供。不要创建假 key 来“通过检查”。合并配置时保留已有 terms、hotwords、manage 等未知字段，原子写入；先备份，不覆盖其他插件文件。

可选 manage.start 是启动命令数组，使用绝对路径；具体字段按 asr-lifecycle.js 核对。只管理自己启动的进程，不终止用户原有 ASR 服务。默认先验证外部服务接通，第二步才加自动托管。

## 4. HTTP 契约：这是必须对齐的部分

当前 asr.js 的 transcribe()：

1. FFmpeg 提取当前片段音轨为 16 kHz、单声道 WAV。
2. POST `{baseUrl}/audio/transcriptions`，multipart/form-data。
3. 字段：file、model、response_format=verbose_json；可选 language、hotword。注意源码字段是单数 hotword。
4. 有 key 时携带 Bearer Authorization。
5. 期望 `segments: [{start, end, text}]`，start/end 单位为当前音频切片内的秒；可选 model、language、text。
6. 上游将片段起点加回 start/end，归一化为视频绝对 from/to。服务端不可再次加视频偏移，否则会重复偏移。

只有 text 没有 segments 时，上游会退化成整段一句。这可以显示文本，但不能作为“逐句时间同步已通过”的证据。适配时校验有限数字、起止顺序和片段范围，不猜造精确时间戳。本地服务接口不兼容时只写薄协议适配层。

## 5. 数据流程与费用控制

保留上游来源选择：显式字幕文件 → 可用站点 CC → 可用内嵌字幕 → ASR 回退；具体可用条件遵循 transcript-pass.js。没有权限获取字幕和视频确实没有字幕要分别显示。

```
当前视频/播放段
  → 复用视频下载缓存
  → 查字幕及转写缓存
  → 有可用字幕：直接使用，ASR 请求为零
  → 无可用字幕且有音轨：对所需片段识别
  → 时间归一化 + 来源标注 + 缓存
  → 原版 watch_together 分镜/台词流程
```

- 不按画面采样频率调用 ASR，不在每次 UI 查询状态时转写。
- 复用原分段与预取机制；快进/换片使旧输出失效，避免重复抽整部视频。
- 对同一媒体、片段、识别配置并发去重。配置变更的缓存隔离至少核对 model/baseUrl/language/hotwords 等上游键；术语修改是否影响缓存需专门验证。
- 静音/无音轨可合法返回空，不伪造字幕。重试有限次数并退避，错误不触发昂贵的自动多供应商轮询。
- 停止时阻止新工作、取消自有请求/子进程、丢弃迟到结果。现有 transcribe() 使用超时 signal，不能假定已经接通外部取消；检查并补最小取消传递，或至少保证迟到结果不发布且没有无限后台作业。

## 6. 状态与错误，交给 03 面板消费

建议返回结构化状态：source（subtitle/file/asr/none）、phase（idle/loading/ready/error）、model、最近成功时间、已覆盖时间范围、缓存命中、errorCode。UI 文案由这些字段生成，不解析模型回答。

至少区分：未配置；服务不可达；认证失败；模型不存在；没有音轨；字幕需要登录；正在转写；转写成功但无对白；响应缺少时间戳；超时。沿用上游 no-key、no-audio、asr-unreachable、asr-empty 等已有语义并做稳定映射，不让“没有对白”被统一写成“听不到”。

错误文本不得包含 Bearer token、cookies 或完整服务返回的敏感内容。浏览器端显示 keyConfigured，不能回传原始 key。测试连接先做非付费就绪检查，实际转写测试用明确的短音频；二者分开命名。

ASR 只是把对白转成文字，不代表模型识别全部音乐/音效，也不是麦克风或系统全局监听。不要在本次加入 WASAPI 常驻录音。

## 7. 验收与交付顺序

1. 假 HTTP 服务测试：收到正确 WAV/form 字段；返回切片相对时间，转换后无重复偏移。
2. 有字幕样例：ASR 调用次数为零；无字幕含对白样例：返回可用句级时间戳。
3. 同段重复请求命中缓存；模型/语言变更不误用旧缓存。
4. 无音轨/静音、401、错误模型、超时、非法响应分别给出可理解状态。
5. 暂停、停止、快进、换片：无迟到评论，无新背景识别风暴。
6. 用用户认可的视频实测字幕回退；报告真实耗时/资源使用，不填写理论数字冒充测试。
7. 回归原视频陪看已验收行为、屏幕 Watch 与 Memory Evolve。

可复用检查脚本：scripts/check_watch_together_native.mjs、scripts/check_watch_together_media.mjs。后者是合成视频+SRT 测试，不能替代真实 ASR 验收。Node 测试在沙箱不能 spawn 时用 --test-isolation=none。

交付需含配置位置、依赖固定版本、启动/关闭方式、测试结果、尚未验证项、回退方法。配置回退恢复本次新增字段，原服务保持可用。更新开发包版本和 MIO-DEVELOPMENT.json 哈希，并在 log 写实现记录。
