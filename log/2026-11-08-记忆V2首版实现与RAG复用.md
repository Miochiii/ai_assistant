# 记忆 V2 首版实现与 RAG 复用

日期：2026-11-08。本文是本轮代码交接，承接 `2026-11-07-记忆V2技术方案-复用成熟RAG与每日自动整理.md`，不代表该方案所有阶段已经完成。

## 1. 本轮实际落地

已把成熟 RAG 的检索代码复制到助手项目后适配，完成这条最小闭环：

`面板用户消息 → 本地来源账本 → 跨日待整理批次 → 独立无工具模型抽取 → 来源核验/采纳 → SQLite 有效记忆 → 独立混合检索 → 面板本轮上下文`。

普通聊天中的一部分明确偏好可自动入库，不要求逐条输入“记住”。例如单独一条“教程请一步一步来”或“我平时用 PyCharm 编写 Python 程序”，经次日抽取、核验后可成为有效记忆。模型调用和抽取结果不追加到 Harness 主会话；原有明确交给主会话的入口仍然保留。

这是可运行的第一版核心，自动采纳范围目前限定为沟通风格、语言和常用编辑器。其他普通偏好保留候选；事件摘要、任意个人事实、复杂偏好更新还未开放自动采纳。不要把这版描述为完整自动记住全部对话。

## 2. 代码和数据的独立性

- `third_party/memory_rag/retriever.py`：复制并改造原 `rag_core/retriever.py`，保留 BM25、BGE 向量、RRF 和 BGE reranker。移除对原项目配置、切库、MySQL 过滤和下载路径的依赖。
- `third_party/memory_rag/conditional_cusum.reference.py`：原变点检测代码参考副本，保留原 LICENSE；来源和哈希见同目录 NOTICE 与 provenance.json。
- `scripts/memory_rag_worker.py`：独立进程、本地权重、CPU 推理。只接受 Host 提供的作用域和当前有效记忆快照。
- `runtime/memory/memory.sqlite3`：继续使用助手自身的权威记忆库，新增每日设置、队列、作业回执和租约表，不替换旧表。
- `runtime/memory/indexes/<scope-hash>/<generation-hash>/`：助手独占的派生索引。scope 由可信 Host 绑定用户和工作区；generation 由快照和配置哈希生成。每个作用域用 Windows 文件锁保护 Qdrant 访问。

原 RAG 项目的代码、配置、语料、索引、Python 环境均未修改。**代码和业务数据独立，但当前运行环境尚非完全自包含**：仍只读调用原来的 Python 3.12 解释器与 BGE 权重。解释器及权重路径写在 `configs/memory-v2.json`，以后可以改到助手专用环境；当前没有复制整个 RAG 仓库或大模型权重。

为兼容该环境 NumPy 1.26.4，单独安装 SciPy 1.13.1 到助手的 `third_party/memory_rag_deps`，worker 优先加载此目录，未改动原环境。版本依据与恢复命令见 NOTICE。没有安装 CUDA，没有下载模型。

## 3. 每日采集和自动整理

`src/assistant_memory/v2.py` 负责持久化协议；`plugins/dsh-assistant-host/daily-memory.js` 负责调度和模型抽取。

当前配置仅为本次已授权的 `ai assistant` 工作区启用。新作用域在该工作区内默认开启；没有将该行为推广到别的工作区。面板可输入以下精确命令：

- `自动记忆状态`：查看开关、策略版本及本实例最近整理结果。
- `关闭自动记忆`：停止后续自动采集/整理/语义注入；撤销待处理队列，变更策略版本，清空当前面板短历史。已有记忆不被删除，显式查询功能保留。
- `开启自动记忆`：恢复此作用域后续处理，不回填关闭期间的对话。

只采集带消息 ID 的普通用户面板输入；来源键绑定用户、项目、会话和消息 ID，重投不重复。模型回答、截图、观察播报和主会话历史目前不采集。包含明显凭据关键词或“不要记忆”“不要记住”的整条输入不采集；这不是完备的敏感信息识别器。

按北京时间自然日分组，只整理已经结束的日期。面板开启且当前没有回复时触发检查，每小时最多领取一次，每批最多 20 条、原文合计不超过 40,000 字符；跨日停机的积压在下次面板开启后继续。不是操作系统定时任务，面板关闭时不会后台唤醒。

批次有来源内容、作用域、策略版本的哈希，十分钟租约、最多三次尝试。抽取请求使用当前配置的陪伴模型路由，独立上下文、无工具、最多 4096 输出 token、120 秒超时。运行时会产生正常模型费用；本轮验收使用模拟抽取器，未启动付费抽取试验。

提交前重新核验：来源未删除、内容未变、属于真实用户、仍待处理、同作用域、同策略版本。quote 必须逐字出自来源，不能用模型补全事实。自动采纳还要求整条输入就是该偏好、命中有限规则、无明显否定/转述/假设/疑问；不采纳凭据和规则识别的敏感项。冲突不覆盖旧值，进入候选。采纳与处理水位及结果回执同一 SQLite 事务提交，重投返回既有回执。

失败不会推进处理水位。达到三次上限会停止该批；当前需维护者查看并处理阻塞批次，尚无用户界面的失败队列。长对话中的偏好摘句通常只形成候选，这是本版有意收窄的范围，后续可用真实标注数据扩展规则。

## 4. 检索与上下文失效

RAG 仅索引当前作用域的有效记忆，候选、撤销、过期、被替代和失效依赖不进入快照。旧 V1 `assistant-panel` 便笺仍保持原来的“显式查询”契约，不悄悄迁移到自动注入；`panel.guidance.style` 设置不混入普通 RAG。曾有人工指导设置时，它优先于自动提取的沟通风格，停用也不会被旧 RAG 内容绕过。

每轮最多返回五条记忆，面板注入最多 6000 字符，并标明是参考资料，不是指令或授权。索引不可用、目录被占用、解释器异常或超时时降级到 SQLite 字面检索；降级返回仍受当前有效集合过滤。

完整有效集合生成版本指纹。检索后再次核验版本；模型请求前、回复后再通过 `rag_version` 检查。版本变化或复查失败时清空相关短历史，拒绝展示本次结果。这样能处理推理期间发生的撤销，但无法撤回已经发送给模型提供方的内容，也不声称消除所有检查后瞬间变化的竞态。

现有实现每次检索启动独立 worker，模型冷加载可能有数秒以上开销，检索上限 90 秒，与面板总请求时限共享时间。适合先验证正确性；大规模记忆、高并发和低延迟尚需常驻 worker、增量投影及专门评测。索引以完整快照生成新代次，尚非增量 outbox/原子 active pointer 架构。

## 5. 变点检测和删除语义

`src/assistant_memory/quality_monitor.py` 是依据原条件 CUSUM 似然公式适配的影子监测组件：已评价的二元损失推进统计量，unknown 单独计数，同事件幂等，profile 改变要求新 epoch。结果固定 `calibrated=false`、`action=diagnose_only`。

本轮未把它挂到真实在线反馈流，也没有记忆场景阈值校准；不会因报警自动删除、清空或重建权威库。

撤销/遗忘后记忆不会再通过当前有效快照注入，但**旧代次向量和部分文本 payload 目前仍可能留在磁盘**。本版没有完成旧索引代次 GC、所有副本的物理擦除，也没有实现 30 天自动清理。配置明确使用 `manual_until_retention_worker`，不能宣称“已自动物理删除”。关闭自动记忆也不是删除。后续 M5 必须补齐删除账本、旧代次清理和可验证删除报告。

## 6. 验证和使用

本轮验证包含合成数据的来源核验、跨作用域拒绝、来源删除/开关变化、批次幂等、冲突候选、故障降级、版本撤销，以及原显式记忆/指导设置回归。Node 模型使用模拟 stream，没有付费请求。

最终结果：新增 Python 测试 11 项、原核心 31 项、原自动化 15 项、Node 面板/Host 测试 22 项全部通过，共 79 项。Windows 沙箱中的 Node spawn EPERM 和 Python 临时目录权限问题通过在允许创建进程的环境运行解决；失败产生的九个临时目录已定向清理，集成测试遗留的单条合成索引也在核验内容后删除，未删除旧有 tmp 或正式 memory.sqlite3。

本地真实 CPU 检索使用七条合成记忆，问题“我常用什么开发软件？”首条返回“我平时用 PyCharm 编写 Python 程序”；候选数量大于五，经过 BGE reranker。测试完成后删除自己的索引分区。

在项目根目录可复核：

```powershell
& 'E:\file\agent\python.v\.venv\Scripts\python.exe' -B tests/test_memory_v2.py
& 'E:\file\agent\python.v\.venv\Scripts\python.exe' -B tests/test_memory.py
node --test tests/test_daily_memory.mjs tests/test_memory_host.mjs tests/test_assistant_panel_model.mjs tests/test_companion_memory.mjs
& 'E:\file\agent\python.v\.venv\Scripts\python.exe' -B scripts/check_memory_rag.py
```

需要下次完全重启 Harness 加载修改，再开启面板。先输入 `自动记忆状态` 验证接入；自然日结束前不会立刻整理当天输入。旧会话不会被扫描回填。真实 Harness 的跨日在线效果尚需运行验收，不能用离线测试代替这项结论。

保持现有代码方向，继续补齐通用偏好/事实抽取评测、人工更正与自动条目的冲突归一、阻塞作业管理、持久化注入账本、旧代次物理清理和常驻检索服务。不要为扩大“自动记忆率”绕过来源核验，不要把记忆授权转换为动作授权；变点报警先定位索引/来源/偏好变化原因，不能直接清空库。
