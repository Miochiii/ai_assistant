# Orb 首批记忆入口接入与验收

开发包版本更新为 `0.2.1-mio-dev.2`。本轮直接修改用户 DSH 已指向的 `dsh_orb_full_orig`，新增 package export `./memory-host` 及应用级 bundle 条目。当前 C 盘 profile 可解析新入口到 E 盘；模块导入与 host JS 语法检查通过。没有重启或关闭用户应用，运行中加载待重启后确认。

## 接入范围

- `plugins/dsh-orb-memory/host.js` 负责应用级服务、来源事件监听和每分钟空闲检查。复用已有 DailyMemory：每小时最多一次领取已结束日期批次，SQLite 租约/幂等/来源校验仍生效。
- 普通前台 Computer Use 消息只在指定 `dsh_orb_work` 工作区被采集；后台 standard 会话、工具输出、runtime context、后台通知不作为用户偏好。真实 session/RPC 标识用于去重，不扫描旧历史。
- Orb runtime 的真实 `onPrompt` 增加本地命令入口，在 preempt 前处理，不取消正在运行的普通任务，不将控制命令或查询正文送入模型/Harness 历史。圈选截图上的记忆命令提示改用纯文本。
- 状态/开关命令仅由该 UI 入口执行，session/event 中的同名文本不会修改 consent。
- 显式 `记住：` / `查记忆：` 复用旧 Host 的人工便笺接口，映射到原项目作用域，保留其显式查询契约；此类便笺仍是原 assistant-panel 来源标签，自动普通消息使用 orb_daily。不会将两者悄悄改为自动注入。
- 整理使用配置中的 deepseek-official / deepseek-flash，无工具独立请求；领取有效待整理批次后会产生正常模型费用。本轮仅用假模型/测试库验证，未调用付费模型。

## 可在悬浮球中输入

1. `自动记忆状态`：确认本地入口已加载、开关、采集与整理状态。
2. `记住：验收代号是星桥`：明确保存一条测试便笺，应直接显示“已记住。”。
3. 新建 Orb 会话，输入 `查记忆：星桥`：应显示刚才保存的便笺。
4. `关闭自动记忆`：后续普通消息不采集/整理，取消待处理队列；已有记忆不删除，显式查询仍可用。`开启自动记忆` 恢复后续处理，不回填。
5. `整理昨日记忆`：空闲时立即检查已结束日期批次，不强行整理当天内容。普通偏好跨日整理后可用“查记忆：关键词”查看。

本地回复目前只在 Orb 的临时 UI transcript 中显示，没有写入持久模型对话历史，重开旧会话时不保证重放这些本地气泡。便笺本身在 SQLite 中持久保存。

## 验证

- 11 项 Node 测试通过，覆盖来源桥接、本地控制、异作用域拒绝、关闭与卸载、原每日整理和失效逻辑。
- `scripts/check_orb_memory_service.mjs` 使用当前开发包**实际 onPrompt 方法体**、模拟 UI 和真实 Python CLI/临时 SQLite：状态、本地显式写入、第二会话查询、关闭后采集返回 disabled、已有条目查询、圈选拒绝、普通聊天仍进入原路径均通过；控制命令没有模型请求。报告 `results/memory/orb-ui-memory-smoke.json`。
- `dsh-orb-mio-dev/memory-host` 从实际 desktop profile 解析到指定 E 盘包，导入导出的 inject/apply 验证通过。
- 尚未在用户真实悬浮球运行验收，跨日真实模型抽取仍待观察。没有读写正式记忆数据做测试。

## 明确未完成

普通聊天自动召回/上下文注入、切换状态自动初始化与代次切换编排、后台完成通知确认、人格配置尚未接成完整线上链路。本轮没有开启 memoryCutover 门禁，以免未初始化状态阻止当前会话。不能把显式跨会话查询通过称为自然语言自动记忆已经完整完成。

下一步先确认用户重启后的本地入口与来源采集，再在这个已接入包继续自动召回与失效切换。保持已实现入口，不再让用户只验收 runtime 临时副本。
