# Orb 手动 Watch 第一阶段

用户已验收 dsh-memory-evolve，批准转入 Watch。开发版为 `0.2.1-mio-dev.8`，通过既有 C 盘 profile Junction 加载 E 盘开发目录；本轮无需修改 profile 配置，也没有改动成熟记忆插件或已验收的记忆数据。

## 当前实现

- Orb 普通输入和插话入口拦截三个精确命令：`开始观察`、`观察状态`、`停止观察`。命令不提交模型；自然语言中的引用不会误触发。
- 默认一次演示限定在显示器 1，包含该屏幕上可见的窗口和 Orb 面板。开始回复说明范围，3 秒后开始，每次采样完成后间隔 2 秒继续。此阶段没有窗口选择器，也不录制鼠标/键盘事件。
- 复用现有 MSS Python 截图助手和 `FrameChangeAnalyzer`。保留首帧、本地检测到变化的帧与几何变化帧，其余丢弃。这里使用的是现有采样网格画面差异，未将原 RAG 的统计变点检测直接用于筛帧。
- 每次运行建立 `runtime/watch/<UUID>/manifest.json` 及编号 PNG。原始 RGB 和中间截图在每次采样后清理，不写入记忆，不向模型上传。
- 状态气泡显示正在观察/已停止、采样次数、保留帧数、停止原因和记录文件路径；没有使用旧的检索记忆底部提示区域。
- 用户停止会取消在途截图并等待退出；迟到截图不写入记录。新普通对话/操作任务、会话切换、停止按钮、Orb halt 或插件卸载结束观察。已有操作任务、后台运行任务或待处理问答时拒绝开始。
- 单次最多 5 分钟、60 帧或 100 MB；采样/存储错误停止，不能以成功状态继续。重启不自动恢复采集。保留记录目前由用户管理，不自动删除历史。

## 验收

完全退出并重开 DSH，确认开发版加载为 `.8`。

1. 在 Orb 单独发送 `开始观察`，应出现本地 Watch 回复，包含显示器 1 与 3 秒延迟。
2. 切回桌面，在显示器 1 上演示开始菜单 → program → PyCharm。为了让 2 秒采样看到中间画面，每个界面停留约 3 秒。
3. 发送 `观察状态`，应显示采样次数和保留帧数。保持静止时不应每次都新增帧；面板、鼠标、动画或时钟变化仍可能触发保存。
4. 发送 `停止观察`，应显示已停止、最终计数和记录路径。等待几秒后再次查询，计数不再增加。
5. 检查该目录的 PNG 和 manifest：应有实际桌面变化，`model_calls: 0`、`semantic_analysis: not_run`、`memory_written: false`。本阶段不要求她复述步骤；下一阶段才加语义识别和摘要。

观察结果是采样画面，不是完整视频、点击日志或已经学会的流程。快速闪过的菜单可能漏采；单屏范围不覆盖另一显示器。显示器 1 的编号沿用现有 MSS 入口，若目标在另一屏，应先停止并调整后续范围入口。

## 验证结果

- `node --test --test-isolation=none tests/test_orb_watch.mjs tests/test_orb_task_memory.mjs`：20 项通过。涵盖空闲零采样、重复开始、静帧过滤、变化与几何变化、帧数/体积/时间上限、采样失败、取消迟到结果、单飞、生命周期和真实 Orb 方法的本地命令分流，以及记忆隔离回归。
- `scripts/check_orb_watch.mjs`：真实本地截图 2560×1440、PNG 有效、临时 RGB/截图清理、模型调用 0、桌面输入 0。测试截图已删除，只保留 `results/watch/local-capture.json` 数值报告。初次运行因沙箱阻止子进程返回 EPERM，允许的提权自检随后通过；未改变应用权限。
- Orb host 语法检查通过。没有替用户重启 DSH；真实 Orb 界面命令和完整演示仍待用户验收。

异常退出可能来不及写停止状态，历史 manifest 的 recording 不代表当前仍在采集；程序不会根据旧记录恢复观察。此阶段未做自动语义摘要、记忆候选确认桥接、Teach 演示纠正或自动重放。
