# Orb 任务准备失败：混合记忆格式兼容修复

用户真实验收“帮我打开 Python 开发工具，在名字是program的磁铁盒子里面。”时，界面提示记忆任务准备未完成，未提交操作。开发包修复版为 `0.2.1-mio-dev.5`。

只读诊断使用实际 MemoryHost、当前记忆库及上述查询，未调用模型或执行桌面操作，也未输出记忆正文。修复前精确复现 `MEMORY_RECALL_INVALID`：五条召回结果包含一条字符串和四条结构化对象。底层网关允许结构化 episode/checkpoint 记忆，但新增 `readTaskContext` 错误地限制 content 必须为字符串，导致整项任务被拒绝。

修复保留结构化 JSON 对象/数组作为上下文数据，与字符串偏好一并序列化；不转换为代码或指令。原五条/6000 字符上限、开关、代次检查、工具权限和持久失效门禁不变。缺失 ID、undefined/null 等无效记录仍拒绝。

24 项相关 Node 测试通过，新增混合格式保真及畸形记录拒绝用例。此前原生任务夹具主要使用单条字符串偏好，未覆盖真实库混合召回，是本次漏测原因。

诊断脚本为 `scripts/diagnose_orb_task_memory.mjs`；仅用于明确授权的本机问题诊断，不作为普通测试读取正式数据。修复后复查同一句任务的准备阶段；不把准备成功称为已经完成真实桌面打开动作。用户需重启 DSH 加载修复版后继续实际验收。
