# Orb 开发副本：切换事务与持久门禁

本轮继续干净会话验证，已实现开发版切换服务、磁盘状态、Orb host 薄适配及可追踪开发副本。**尚未安装，未修改正式 Orb/profile/记忆库，未运行真实悬浮球验收。**

## 实现

- `cutover-store.js`：状态格式校验、临时文件写入/文件 sync/rename/回读；不保存正文。缺失或损坏不自动重新初始化。
- `cutover-service.js`：显式首次登记、预期修订检查、先持久记录旧会话停用与 pending 目标，再保存绑定、更新 UI、提交完成。失败保留恢复状态；恢复沿用目标 ID，不另建会话。磁盘绑定出现第三个 ID 时拒绝覆盖。
- `orb-host-adapter.js`：在 Orb runtime 内挂载 `orbMemoryCutover` 服务，使用原生 `agent/pre-step` 与 `llm/stream` 检查；状态/代次不可用、停用会话或切换中均阻止相关请求。每个流片段放行前复核代次，推理中变化会阻止后续工具片段继续交付。已经显示的片段无法撤回，已经开始的工具动作不声称可回滚。
- 真实用户输入入口 preempt/newSession/openSession 串行化。切换/恢复期间返回明确 pending 错误，不自动重试。尚无跨进程持久输入队列，不能声称崩溃后用户消息自动恰好投递一次。
- 不直接调用吞掉保存失败的 `remember`；开发副本新增 `applyMemoryBinding`，只在保存并回读成功后更新 runtime、screen owner、UI 和水位。

## 开发副本

`scripts/prepare_orb_memory_dev.mjs` 从安装的 Orb 0.2.1 生成 `runtime/dev-orb-memory/orb`，仅补一个 opt-in host 服务入口和绑定方法，三份扩展 JS 随副本复制。`manifest.json` 记录安装版 host、副本 host 和扩展文件 SHA-256。构建器拒绝覆盖既有目录，不修改安装源。

仅当 host 配置显式包含 `memoryCutover.stateFile` 才启用。状态文件应放 E 盘。需要独立记忆插件提供 `orbMemoryGeneration.current()` 非空代次；当前未连接真实 V2 版本提供器。首次登记要求当前空白会话；缺失状态时可新建会话，但相关模型请求仍被阻止，直到显式完成登记。自动注入尚未启用。

## 验证

- 18 项 Node 测试通过（本轮磁盘事务 7 项，前轮准备 6 项、来源桥接 5 项）。覆盖保存绑定、更新 UI、最终提交的故障；磁盘重载后恢复；损坏/缺失状态；第三方绑定冲突；忙碌与陈旧修订。
- `check_orb_cutover_native.mjs`：真实安装 SDK + 假模型 + 模拟 Orb runtime，使用磁盘切换状态和绑定文件。5 次假模型请求、1 次合成工具执行；旧会话通知被真实请求钩子阻止，恢复后的门禁仍有效；推理中版本变化后的工具调用未执行。报告 `results/memory/orb-cutover-native-20261110.json`。
- 生成的 host JS 与适配模块通过 Node 语法检查。没有加载完整 Orb UI、没有网络/付费模型请求或桌面动作。

## 当前保守边界与下一步

1. Orb 后台 registry 没有通知投递确认。开发适配要求当前 caller 没有任何后台登记，包括已完成记录；否则暂缓。不能把 done 直接当作无待投递消息。
2. 开发版要求 lasso 功能关闭、无待处理选择或翻译，避免在没有明确生命周期信号时清掉用户交互。真实 UI 所有输入路径尚未验收。
3. 切换服务假定同一状态文件只有一个应用级写入者；尚未实现跨进程排他锁与断电级事务保证。文件 sync+rename 不能宣称覆盖所有断电场景。
4. 原生夹具真实验证了 Harness 钩子和磁盘状态，Orb runtime/UI 仍为模拟；真实会话磁盘 persistence、停用独立记忆插件后的降级、完整恢复交互仍待验收。
5. 下一步先补真实 V2 代次提供器、跨进程单写者约束和后台通知确认，再在隔离 profile/测试库加载开发副本，验证 UI 和恢复。通过后才准备正式配置变更，不要求现在重启。
