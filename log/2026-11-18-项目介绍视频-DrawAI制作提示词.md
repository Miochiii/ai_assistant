请使用已安装的 dsh-drawai 插件，制作一个中文 AI 助手项目介绍视频。直接完成分镜、工程制作、预览检查、配乐和导出；遇到真正缺失的素材或工具再说明，不要只返回策划方案。

## 一、定位和叙事

项目名使用“AI 助手”，副标题“记忆 · 操作 · 陪伴”。这是基于 DSH 与 Orb、复用成熟插件并做本地增强的个人桌面助手，不要包装成所有能力都从零自研。

核心问题：我经常用手机远控电脑开发，手机上找按钮、切换键盘、输入路径都很麻烦。我希望向 Orb 发一句话，它能记得我的习惯、打开软件并执行操作；闲下来也能陪我浏览屏幕和看视频。

视频围绕“记得你 → 替你操作 → 陪你看”展开，以用户价值解释技术，不做版本更新日志或功能名堆砌。

默认制作约 90 秒、16:9、1920×1080、30fps 的简约产品介绍视频。无配音，以 BGM、简短中文标题与画面讲清楚；不要自动新增 TTS 或购买素材。每屏一个主信息，标题约 8–16 字，辅助说明最多两行。正文需在手机横屏上可读，不把整个桌面缩成看不清的小窗口。

## 二、风格

暖白/浅灰底、深灰文字、单一蓝色强调；统一中文无衬线字体、充足留白、细线和轻圆角。少量深色镜头用于章节分隔即可。

使用轻微位移、淡入淡出、局部推近与简单路径动画。避免霓虹、赛博粒子、炫光、复杂 3D、快速闪烁和花哨转场，不做“十张卡片不断轮播”的模板片。

贯穿画面的是一个小型 Orb 球和简洁的文字指令气泡。真实界面优先局部展示；没有可用录像时用抽象界面示意，并标注“功能示意”，不能伪造成真实操作录像或验收证据。

## 三、BGM 必须用这首

源文件：`E:\file\agent\drawing\bgm\ZHENLOE - We Never.mp3`。

先探测真实时长与可用音轨，再分析可检测的节拍/强弱变化。不要根据曲名臆测风格、BPM、高潮或人声时间。不要引用或自动转写歌词。

当前制作会话的工作区应为 `E:\file\agent\ai assistant`。若本地导入因源文件不在工作区而被拒绝，可复制一份到工作区 `assets\intro-video\ZHENLOE - We Never.mp3` 后导入；保留原文件。同名文件已存在时先核对内容，避免覆盖不同素材。

复用插件真实工具流程：audio_asset 导入为 bgm，motion_audio 将其加入视频节点的时间轴。不能只添加音频节点就认为成片带音乐。path 是当前画布路径，nodeId 是实际返回的视频节点 ID，不要把示例名称当 ID。

选取连贯、适合约 90 秒的片段，开头约 1.5 秒淡入、结尾约 3 秒淡出，避免突然截断。尽量不循环带人声乐段。音量以不削波、播放舒适为准，使用工具检测，不把固定增益当作听感保证。字幕主导无需刻意压成旁白底噪。若可靠检测到节拍，章节切换适度贴拍；BPM 为 null 时按画面节奏剪辑，不强制踩点。

## 四、分镜与屏幕文案

时间是目标，可按实际音乐在总长附近微调，保证文字阅读时间。

| 时间 | 内容与画面 | 建议主文案 |
|---|---|---|
| 0–8 秒 | 手机边框内的电脑桌面示意，指针、键盘切换出现两三次，然后收束为一个输入框 | “电脑在远处，操作不必繁琐。” |
| 8–17 秒 | 一个小 Orb 球出现，输入“帮我打开 PyCharm”；简洁软件窗口随之呈现 | “一句话，从想法到操作。” |
| 17–32 秒 | 用户偏好、机器环境、项目约定三层信息逐步连接；用“我习惯用 PyCharm 写 Python”到新会话回答的例子 | “记得习惯，也分清项目。” 辅助：“跨会话记忆 · 按需加载操作技能” |
| 32–48 秒 | 展示 PyCharm、VS Code、微信、QQ、ChatGPT 等已记录的常用启动入口；随后展示一次文本输入/快捷键的简洁示意 | “常用软件，不必反复寻找。” 辅助：“启动 · 点击 · 输入 · 快捷键” |
| 48–60 秒 | 局部工具栏，文字“增大字体”对应一个按钮高亮；点击后展示命中信息与界面变化提示，不用密集代码 | “点击之后，也要知道发生了什么。” 辅助：“控件名称定位 · 命中反馈 · 变化检查” |
| 60–70 秒 | 普通网页/工作界面旁的小 Orb 和两行浮条，显示简短陪伴文字；手动切换屏幕/视频模块 | “工作时帮忙，浏览时陪伴。” 辅助：“屏幕陪伴 · 可调节奏 · 自定义人设” |
| 70–82 秒 | 自制无版权争议的视频示意、播放进度、分镜与字幕轨；无字幕时从音轨连到“本地语音识别” | “跟着播放进度，一起看。” 辅助：“分镜与字幕 · 本地 ASR · 开始 / 暂停 / 停止” |
| 82–90 秒 | 三个关键词回到 Orb 周围，收束到干净标题画面 | “AI 助手” / “记忆 · 操作 · 陪伴” / “让电脑操作，更接近一句话。” |

“帮我打开 PyCharm”的一句话不要延展成“打开项目、修改代码、运行测试全部完成”的虚构演示。片尾可小字标注“个人开发项目 · 持续迭代”，不加未经提供的姓名、网址、二维码或成绩。

必须保持的边界：

- UIA 按名称定位只在应用提供可识别控件时适用，不宣传所有软件都精准识别。
- 像素变化仅是反馈，不等于任务成功；不写“零误点”“百分百完成”。
- 屏幕陪伴不是视频音频识别；本地 ASR 属于视频对白处理，不能说模型持续听到整个电脑的声音。
- 陪伴观察不会自动变成用户长期记忆，不表现成看见什么就记住什么。
- 软件启动已验证，但任意多步开发流程和完整手机远控链路不能一概宣布全部完成。手机远控是设计场景，不是独立手机客户端。
- Teach、专用 GUI 大模型、区域搜索算法等规划不得冒充已实现功能。
- 不宣传插件包里存在但本项目未启用/验收的跨设备同步、主动通知等能力。
- 不展示真实聊天内容、API key、私人路径或用户记忆原文；使用已知无敏感内容的片段或示意素材。

## 六、制作与交付

先创建可编辑工程并建立素材索引。先检查一个定调镜头和一个文字最密集镜头，再完成全片，避免最后发现字体/布局不对。选择插件现有可用的 motion 工程流程，不通过改插件安装目录实现视频。

真实素材不足时，使用上述抽象示意方案直接推进；不要为拍宣传素材自动发送消息、修改真实项目、执行危险动作或启动不必要的外部任务。

导出后检查每一段是否有黑帧/遮挡/文字截断/字幕时间不足，确认 MP4 真的存在音轨、音乐贯穿所需时段并有淡出。复用 motion_preview、motion_qa、motion_audio_verify 等实际可用工具；没有试听能力时如实说明“已检查音轨和电平，听感待用户确认”。不得把分析结果写成已经试听。

成品保存到工作区 `output\intro-video\`，文件名建议 `AI助手-项目介绍.mp4`。同时保留可编辑画布/视频工程、时间轴、素材索引和简短制作说明。若插件对输出目录有约束，使用其支持的工程目录完成后再复制成片，不绕过路径校验。不要覆盖已有不同版本成片。

最终回复给出成片路径、实际时长、分辨率、所用 BGM 片段范围，以及有无待确认问题。公开发布前音乐使用授权由用户核对，不要把这首音乐标成免版权。
