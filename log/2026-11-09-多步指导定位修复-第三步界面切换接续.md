# 多步指导定位修复：第三步，点击后的界面切换接续

本轮按用户澄清调整重点：日常路径是点击后菜单展开、弹出对话框或打开独立窗口，再定位下一步，不以指导中移动窗口为主要场景。

## 修改后的行为

### 原窗口内菜单与所属对话框

原来已允许原窗口及其拥有的前台对话框，并截取两者并集。本次增加 Windows 原生菜单窗口（class #32768）：枚举前台进程的可见菜单，将菜单边框加入截图区域和 window_geometry，避免展开的菜单超出原窗口边缘后被裁掉。不同进程的菜单不纳入。

主窗口、前台对话框、菜单分别记录 HWND 和可见边框；最多 16 项，超过则拒绝本次捕获。绘制层仍逐项校验。这是原生菜单支持，不宣称覆盖所有应用自绘、跨进程或无可枚举窗口的弹出层。

### 独立新窗口

当已绑定的目标出现 different_foreground_window、target_hidden_or_minimized 或 target_identity_changed：

1. 清除旧高亮。
2. 改为桌面观察，截图时隐藏助手面板。
3. watch 继续等待画面稳定；仅出现新窗口不会推进任务。
4. 步骤验证模型根据任务、当前步骤、可见完成条件判 passed / failed / unknown。提示明确要求无关软件切换为 unknown。
5. passed 时提供下一步目标；若无下一步可见目标或是最后一步，提供完成证据窗口内部的归一化坐标 evidence_window.position。
6. 根据本地窗口列表确定坐标对应的窗口，再取新截图，确认该窗口身份、边框和画面仍一致。
7. Host 在确认任务未取消、上下文未改变之后，才提交新的 target_window 和观察基线，推进一步并显示下一步提示。

用户正在助手输入框交互、助手尚未退出前台等临时错误不会触发此回退。failed / unknown、缺失定位锚点、窗口确认失败不会改绑。目标选取、步骤成功判断仍是只读指导，不授予点击或输入权限。

## 修改文件

- panel-session.js：绑定窗口失败时桌面回退；validateStepFrame 对桌面切换结果做本地窗口确认。
- panel-guidance.js：增加界面切换验证提示和 evidence_window；无可定位完成证据则 unknown。
- resident-host.js：通过验证及取消检查后提交新窗口绑定和基线。
- task-watch.js：桌面观察时将窗口列表几何纳入变化判断。
- watch_window.py：纳入同前台进程的原生弹出菜单。
- protocol.js、coach_overlay.py：几何绑定列表上限由 2 扩为 16，仍逐项校验。
- test_guidance_transition.mjs、test_task_watch.mjs、test_watch_window.py：新增回退、接续和菜单捕获回归。

## 验证与限制

34 项 Node 测试、8 项窗口绑定 Python 测试、3 项绘制几何 Python 测试通过，共 45 项。测试使用合成帧、模拟模型及模拟 Windows 接口，没有付费 API 调用、真实截图或键鼠操作；测试目录由 finally 清理。

验证覆盖：菜单超出主窗口；其他进程菜单排除；独立窗口回退但不提前改绑；助手焦点不触发桌面回退；缺失完成证据拒绝推进；最后一步的证据窗口锚点；验证期间窗口身份变化拒绝；通过后切换下一步基线；任务取消与迟到结果隔离。

真实软件效果尚未验收。稳定性复核仍沿用粗网格 sameScene，局部变化漏检和窗口局部精定位尚待后续处理。新窗口存在只是候选证据，模型判 passed 也不是形式化正确性证明；需要用实际软件的可见完成条件验收。

## 用户验收

完整重启 Harness 后，在记事本等无重要数据的测试窗口发起多步指导：

1. 打开菜单，检查下一步是否定位菜单项，尤其菜单超出原窗口边界时。
2. 打开字体等对话框，检查下一步提示是否在对话框中。
3. 测试一个确实会打开独立窗口的任务，检查原窗口提示撤下后能否接续。
4. 在等待操作时切到无关软件，确认不会仅因新窗口出现就宣布该步骤完成。

下一步根据以上真实验收结果，再处理局部像素变化复核与窗口内精定位；不通过额外乘 DPI 系数掩盖识别偏差。
