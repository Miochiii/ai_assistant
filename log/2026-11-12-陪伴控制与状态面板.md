日期：2026-11-12。开发包 `dsh-orb-mio-dev` 0.2.1-mio-dev.12。

本文只覆盖 03（面板与控制）。**02（ASR）没有动**：面板里对白来源在无字幕时显示“暂无 / 语音识别未配置”，这正是 02 完成前应有的样子。

## 1. 解决的那个问题

以前设置页只有“陪伴模块”下拉框 + 保存按钮，而运行状态没有任何出口。用户把下拉框改成“视频陪看”却没有保存，看到聊天里有文字回复，就以为视频位置桥已经连通 —— 界面无法证伪。

现在把三件事分开显示，并且控制按钮只作用于**已保存**的模块：

| 显示 | 来源 |
|---|---|
| 已保存：屏幕陪伴 / 视频陪看 | `runtime/companion/settings.json`，只有 POST 成功才变 |
| 未保存：改为… | 前端 draft 与 saved 的差异，保存失败时已保存标记不动 |
| 正在运行：模块 · 阶段 | 两个模块各自的真实运行状态（见 §4） |

## 3. 接口契约

```text
GET  /.dsh-orb/companion-status           纯读；不建段、不启桥、不读 cookies、不调模型/ASR
POST /.dsh-orb/companion-control          {action: start|pause|resume|stop, requestId?, expectedRevision?}
```

- 状态里 `revision` 只在**控制动作被接受**时 +1，轮询不会推高它；`expectedRevision` 对不上返回 409 并附最新快照，前端直接用它覆盖本地显示。
- `requestId` 幂等：同一个 id 重放只返回上次结果（`replay: true`），连点两下只执行一次。
- 控制串行：队列里不会 await 会重入同一队列的方法（`preempt` 间接走 `stopTurn`），避免死锁。

状态字段（面板只消费字段，不解析任何模型文案）：

```text
selectedMode / runningMode / mismatch / sessionId / phase
phase: stopped | starting | running | paused | stopping | unknown（读不到原插件模块时）
bridge: {service: up|down|disabled, extension: live|seen|none|disabled, fresh, ageMs, helloAgeMs}
media:  {title, positionSeconds, durationSeconds, confidence, paused}
transcript: {source, phase, ready, fed, inflight, lines}
screen: {state, samples, calls, spoken, intervalSeconds, lookSeconds, speakSeconds, proactive, backoff, reason}
video:  {available, loop, active, paused, segments, spoken, segment, reason}
lastError: {code, text, at} | null
sources: {loop: module|none, bridge: file|none}
```

## 4. 状态从哪来（这是最容易撒谎的一段）

- **屏幕陪伴**：`OrbCompanion.snapshot()`，直接读内存里那个 run 的事实（state/samples/calls/spoken）。
- **视频陪看**：同进程、同模块实例的 `loopStatus()`。原插件 `public-api.js` 不导出它，循环是 `watch-loop.js` 的模块级单例；profile 里的插件是 Junction，Node 的 ESM 按 realpath 认模块，所以从工作区同一路径 import 拿到的是同一个 `loop`。**不能另起子进程**（那会是空循环），也不为了查状态调 `statusOnly`（它会探浏览器并读盘，太重）。
- **位置桥三层**：读原插件落盘的 `position.json` / `extension.json`（`readBridge` / `readHello`），与模块实例无关。服务可达性单独做 1.5 秒缓存的 loopback 端口探测。
- **对白来源**：`loopStatus().transcript.last.source`，按 `transcript-pass.js` 的词表逐项翻译；“没有对白”和“拿不到字幕”不合并。

## 5. 控制语义

| 动作 | 屏幕 | 视频 |
|---|---|---|
| start | 复用已验收的 `control('开始陪伴')` | 提交一条原生代理指令（同一句措辞），**不 await 整轮**，先显示“启动中” |
| pause | `control('暂停陪伴')` | 直接调原插件 `stopWatchLoop('panel-pause')` + 清语音队列，零模型请求 |
| resume | `control('继续陪伴')` | 重新提交指令，按当前真实播放位置恢复 |
| stop | `control('停止陪伴')` | `stopWatchLoop('panel-stop')`，零模型请求 |

- **暂停/停止作用在“正在跑的那个模块”上**：已保存屏幕、实际在跑视频时，停的是视频循环（否则会出现“点了停止还在说话”）。
- 启动前检查：已保存模块存在、插件已加载、无未保存修改、无冲突任务（`turnRunning` 时不提交，避免 preempt 掉用户的普通对话）。
- “匹配不一致”时只拦启动，不拦暂停/停止。
- 启动 90 秒仍看不到循环 `active` 才报“没有启动起来”，不谎报 running。

## 8. 尚未验证 / 已知限制

1. **真实重启后的进程内实例关系**未验证。判据：重启 → 设置页打开面板 → 开始视频陪看 → `正在运行` 应变成“视频陪看 · 运行中”，诊断区 `状态来源` 应显示“循环 可读”。若显示“读不到”或一直“未运行”而实际在陪看，说明拿到的是第二份模块副本，回退方案是把 `loopStatus/stopWatchLoop` 通过 `globalThis[Symbol.for(...)]` 由插件发布、宿主读取（作为可重放补丁记录）。
2. 视频“开始”仍是**一轮原生模型请求**（面板只负责提交，回执来自原插件），不是零 token；暂停/停止是零 token。
3. 暂停/停止只停循环与语音队列，**不取消那一轮正在跑的模型回复**。若代理在停表后又调一次 `watch_together`，面板会重新显示运行中，需要再点一次停止。
4. 屏幕“暂停”沿用原语义（保留可恢复上下文）；继续从当前画面开始，不承诺精准续队列，前端口径已写明。
5. 真实浏览器扩展在线状态、真实视频拖动/换片、连点与切会话这些场景仍要人工点一遍（§9）。
6. ASR 未接入，无字幕视频的对白来源会停在“暂无”；02 的接入不影响本面板字段。

## 9. 重启验收清单（用户执行）

1. 完全退出并重开 DSH（不是关窗口），设置 → Orb 开发版 · Mio，加载日志应为 `0.2.1-mio-dev.12`。
2. 只改下拉框不保存 → 出现“未保存：改为…”，已保存标记不变，`开始陪伴` 禁用；点保存后提示“已保存：…”。
3. 屏幕模式：开始 → 采样/请求/发言计数上涨；暂停 → 计数停；继续 → 恢复；停止 → 归零。
4. 视频模式（浏览器在播视频、扩展已加载）：开始 → 先“启动中”，原插件真的开窗后才“运行中”，桥三行分别正确；暂停 → 显示已暂停且不再说话；继续 → 按当前进度恢复。
5. 故障态：关掉浏览器（应显示“等待播放信息”而不是旧秒数）、停掉 9377 服务（“不可达”）、插件未加载时启动（“插件尚未加载，请重启 DSH”）。
6. 面板开着不动 1 分钟：不应产生任何模型请求（可看诊断区 revision 不变、聊天无新回复）。

## 10. `.13` 补丁：陪看期间不画「观察框」

用户实报：从面板开始陪看后，一条彩色边框框住 DSH 窗口；切到浏览器时边框仍停在旧位置。

定位：那不是陪看画的，是 `dsh_orb_full_orig/dist/computer-use/index.js` 的装饰 ——
`listScreens()` 成功后 `guard.setObservationFrame(screens[0].bounds)` 画一圈（`observation-frame.html/css`，
青紫渐变），**只有下一次列屏幕或 `turn/end` 时才更新/清除**。视频陪看是一轮**阻塞**的模型回合，
从头到尾等不到 `turn/end`，所以边框就钉在回合开始时那个屏幕/窗口的位置上。

改法（不动 dist、不动上游）：`installOrbCompanion` 里包一层 `ctx.get('computerUseOverlayGuard').setObservationFrame`，
陪看会期内（`companionFrames === true`）把 bounds 换成 `null`；开始陪看时先清一次已经挂着的框；
停陪看 / 循环自己停（`onActiveChange`）/ 插件卸载时恢复。指导与桌面任务不受影响。
文字命令（"开始陪伴"）也走同一份记账，所以面板和文字两条入口行为一致。

没有做"让边框跟随窗口"：它是 `showInactive` 的 always-on-top Electron 窗口，跟随前景窗口需要持续轮询并
反复 setBounds，闪烁与迟滞都跑不掉，而陪看根本不需要这个提示。

回归用例：`tests/test_orb_companion.mjs` 的 "companion suppresses the observation frame while watching, and restores it after"。
