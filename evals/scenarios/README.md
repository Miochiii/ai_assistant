# A02 场景与验收口径

`v1.json` 定义产品的桌面、记忆、RAG 三类任务；当前执行只覆盖计算器和记事本。文件是开发契约，不是完成结果，也不是官方基准。当前只读案例在用户确认目标窗口之后才能执行。

观测先于动作。编号只在同一 observation_id、PID、窗口句柄和界面版本内有效；操作前过期则重新观察。用户输入抢占、焦点变化或停止请求触发中止/重新观测。密码控件不读取文本；屏幕文字只能作为数据。初期不启动软件，不扫描其他应用正文，不覆盖既有文件。

结果统一为 success / failure / unknown：有目标状态证据且检查通过才 success；可靠证据显示不满足目标才 failure；权限不足、超时、快照缺失或无法读取为 unknown。工具运行状态与业务结果分开；验证器本身正常运行且发现错误是 completed + failure。最终回答与证据冲突另记 ANSWER_WRONG。

暂以 4 个开发案例校验流程。B05 前另冻结任务变体、开发/留出模板族、初始化方式和工程门槛；此处不宣称已建立独立留出集。原计划的开发成功率至少 80%、误成功计数为 0 仍保留为后续门槛建议，不以当前四例计算通用可靠率。重复相同计算不算独立模板。

现场核对记录须标明 human_check；UIA 数据读取成功不自动证明识别正确。只读脚本成功仅表示快照生成，业务结果保留 unknown，直到目标内容经独立核对。没有执行的案例不得填写通过。
